Layout Navigation und Gruppierung von Elementen 2

  • Universeller .group-Mechanismus — Erweiterung der von .btn-group / .input-group bekannten Logik (nahtloses Verschmelzen der Kanten benachbarter Elemente) auf Avatare, Icons und Badges.
  • Neue Breadcrumb-Varianten — zusätzliche Stile für die Navigationsbrotkrümel, z. B. mit gekürztem Pfad auf Mobilgeräten oder mit Icons zwischen den Ebenen.

Neu Formulare und Felder 5

  • Ausdrucksstärkere Auswahl-Animation — heute hat eine Checkbox/Radio nur einen sanften Übergang von Hintergrund- und Rahmenfarbe (transition); künftig etwas Auffälligeres, z. B. ein gezeichnetes Häkchen oder ein dezenter Pop-Effekt beim Auswählen — weiterhin ohne zusätzliche Klassen.
  • Zeichenlimit und Datenmasken — ein Zähler für verbleibende Zeichen in einem Textfeld sowie fertige Masken für gängige Formate (Telefon, Zahlungskarte, Postleitzahl, Kontonummer).
  • Anzeige der Passwortstärke — eine Leiste oder Beschriftung, die live zeigt, wie stark das eingegebene Passwort ist.
  • Neue Feldtypen — ein Tag-Eingabefeld (hinzugefügt als „Pillen"), ein E-Mail-Feld mit Domänenvorschlägen, eine Personen-/Benutzerauswahl aus einer Liste.
  • Eingabe für Einmalcode (OTP) — separate Felder für einzelne Ziffern mit automatischem Sprung zum nächsten Feld nach Eingabe eines Zeichens.

Neu Buttons 2

  • Zähler, Icon oder Punkt auf einem Button — ein universeller Overlay-Mechanismus: eine Zahl (z. B. für Benachrichtigungen), ein Icon (z. B. ein Plus) oder einfach ein Punkt, der auf etwas Neues hinweist.
  • Ein ausklappbarer Telefon-Button — auf dem Desktop zeigt er nur ein Hörer-Icon und klappt beim Hover zur vollständigen Nummer auf; auf Mobilgeräten ist die Nummer sofort sichtbar, da es dort keinen Hover-Zustand gibt.

Komponente Neue Komponenten 7

  • Ein halbseitiges Modal — eine Variante des Seiten- oder unteren Panels, die genau die Hälfte der Bildschirmhöhe/-breite einnimmt, ähnlich den aus dem Google Tag Manager bekannten Fenstern.
  • Erweiterte Tooltip-Varianten — darunter eine Version, die sich wie ein Mini-Modal verhält, mit eigenem Titel und Aktions-Buttons — idealerweise auf denselben Stilen wie .modal-dialog aufgebaut.
  • Automatischer Kartenrahmen in der Farbe von Header/Footer — wenn Header oder Footer einer Karte eine Farbe zugewiesen bekommt (z. B. .bg-primary), erhält die gesamte Karte automatisch einen Rahmen im selben Farbton.
  • Ein echter Checklist mit abhakbaren Einträgen — .list-icons-check zeigt heute nur dekorativ ein Häkchen-Icon neben jedem Eintrag; es fehlt eine Variante, bei der ein Klick tatsächlich den Zustand „erledigt" umschaltet (auf Checkbox-Basis, ähnlich .selection-tile, aber in Listenform).
  • Ein generisches Galerie-Raster, verknüpft mit der Lightbox — heute funktionieren .product-gallery (Hauptfoto + Reihe von Miniaturbildern) und die Lightbox als zwei getrennte Komponenten; es fehlt eine „Miniaturbild-Raster"-Variante, die sich direkt in der Lightbox öffnet, zur Verwendung außerhalb eines Produktkontexts (z. B. eine Projekt-Galerie, ein Portfolio).
  • Ein generisches Zitat im Artikelinhalt — .testimonial liefert bereits eine stilisierte „Kundenbewertung" mit Autor und Avatar, aber das ist eine Komponente für Marketing-Bereiche, nicht zum Einfügen mitten in einen Blogtext. Es fehlt eine leichtere <blockquote>-Variante unter _blog.scss.
  • Tabellen in mehreren Größen — Erweiterung der vorhandenen .table-sm / .table-lg um zusätzliche Dichte-Varianten für Daten.

Feedback Feedback und Status 3

  • Verschiedene Toast-Arten — darunter eine Variante, die nicht automatisch verschwindet und vom Benutzer manuell geschlossen werden muss.
  • Pulsierender Text — Text, der analog zu .status-ping pulsiert — zu prüfen, ob sich beide Animationen zeitlich synchronisieren lassen.
  • Onboarding — eine leichtgewichtige Komponente, um neue Benutzer Schritt für Schritt durch die Oberfläche zu führen: Hervorhebung eines Elements plus einer Beschreibungsblase.

Effekt Effekte, Animationen und Typografie 6

  • Grafische Filter — brightness, contrast, sepia, saturate als fertige Klassen (heute gibt es nur .filter-grayscale und .filter-blur); auch nützlich als „Vor-Hover"-Zustand (z. B. ein Schwarz-Weiß-Foto, das beim Hover Farbe annimmt).
  • Ein Gradienten-Overlay für Text auf einem Bild — eine fertige Klasse mit linear-gradient, die die Lesbarkeit von Text auf einem Fotohintergrund sicherstellt, ohne die Transparenz manuell abzustimmen.
  • Eine erweiterte Farbskala — mehr Farbtöne und Varianten in der System-Farbpalette.
  • Text als reiner Umriss — eine typografische Variante mit nur der Buchstabenkontur, ohne Füllung.
  • Verbindung von .file-upload-animated mit der gemeinsamen Bibliothek .hover-border-* — die Bibliothek (.hover-border-draw/-trace/-draw-2/-trace-2) existiert bereits, aber .file-upload-animated hat weiterhin eine eigene, separate Implementierung der animierten Umrandung („Marching Ants"), die diesen Mechanismus nicht nutzt.
  • Zu untersuchen Lässt sich in purem CSS die Schriftfarbe an der Stelle sanft ändern, an der sich der Hintergrund darunter ändert (z. B. Text an der Grenze zweier Abschnitte mit unterschiedlichen Farben)?

Data Viz Diagramme und Daten 2

  • Ein Tacho-Diagramm — ein Zeiger auf einer gebogenen Skala, z. B. zur Darstellung einer einzelnen Gesamtbewertung oder eines Ergebnisses.
  • Weitere Stepper-Varianten — zusätzliche visuelle Varianten neben dem vorhandenen .stepper und .stepper-numbered.

Shop Online-Shop 2

  • Hover auf dem Button „In den Warenkorb" vergrößert das Produktfoto — heute wird die Vergrößerung (.product-image-wrapper:hover) beim Hover über das Foto selbst ausgelöst; die Idee ist eine zusätzliche Verstärkung der Reaktion speziell beim Hover über den Aktions-Button, nicht nur über die Miniaturansicht.
  • Eine Animation beim Hinzufügen zum Warenkorb — eine kurze Animation des Produkts, das nach dem Klick zum Warenkorb-Icon „fliegt".

Admin Admin-Panel 1

  • Eine Leiste über .admin-nav (Schnellaktionen, Suche, Benachrichtigungen) — im Framework gibt es bereits .topbar (Kontext der Marketing-Navbar) und .dashboard-header (eine Leiste innerhalb des Panel-Inhalts), aber keines von beiden ist als Leiste direkt über der Admin-Sidebar dokumentiert/angepasst.

DX Dokumentation und Tools 2

  • Icons: Überblick über die Ansätze in der Dokumentation — ein eigener Abschnitt, der CSS-only-Lösungen, JS-abhängige Lösungen und Fallbacks vergleicht, mit einer klaren Empfehlung, wann welche zu verwenden ist.
  • Eine VS-Code-Erweiterung — Hinweise und Autovervollständigung für molique-Klassen direkt im Editor.

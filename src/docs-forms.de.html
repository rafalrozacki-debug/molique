Formulare & Validierung

Formulare für dichte B2B-Oberflächen: eine Klasse für alle Felder, Validierung ohne eine einzige Zeile JavaScript und erzwungene 44px Höhe. Fertige Layouts finden Sie in den Beispielen.

1. Drei Grundsätze

molique-Formulare unterscheiden sich in drei Punkten von typischen Bibliotheken. Wenn Sie diese drei Dinge verstehen, ist der Rest der Seite nur noch eine Klassenliste.

Grundsatz Was das in der Praxis bedeutet
Eine Klasse .input <input>, <select> und <textarea> erhalten dieselbe Klasse. Es gibt kein separates .form-select oder .form-textarea, das man sich merken müsste.
Validierung ohne JS Fehlermeldungen zeigt allein CSS an, über die Pseudoklasse :user-invalid. Sie binden kein Skript ein — siehe Abschnitt 4.
44px Minimum Jedes Feld und jeder Button hat min-height: var(--target-size-min) — Anforderung an das Berührungsziel nach WCAG 2.2 AAA. Unterschreiten Sie diesen Wert nicht.
Bitte geben Sie eine gültige E-Mail-Adresse ein.

Gehen Sie in das zweite Feld, tippen Sie etwas ein und verlassen Sie es — die Meldung erscheint ohne JavaScript.

2. Das Feld und seine Varianten

<input type="text" class="input">
<select class="input">…</select>
<textarea class="input"></textarea>

<input type="text" class="input input-sm">   <!-- niedriger -->
<input type="text" class="input input-lg">   <!-- höher -->
Klasse Auf Was sie macht
.input input, select, textarea Rahmen, Padding, Abrundung, Fokusring und eine Mindesthöhe von 44px.
.input-sm .input Niedrigere Variante für dichte Tabellen und Filterleisten.
.input-lg .input Höhere Variante — Kontaktformulare, Hero-Bereich.
.input-range input[type="range"] Ein Schieberegler mit einheitlichem Aussehen in jedem Browser.
.input-color input[type="color"] Ein Farbwähler als sauberes Quadrat statt der nativen Schaltfläche.
.textarea-expandable <textarea> Ein Feld in Höhe einer Zeile, das sich beim Klicken ausklappt. Erfordert placeholder=" " — siehe Fallstrick Nr. 1.
Zahlenfeld ohne Pfeile

input[type="number"].input hat keinen nativen Spinner — in einer dichten Oberfläche sind diese Pfeile zu klein, um sie zu treffen. Für schrittweises Erhöhen dient die Komponente .qty-input mit den Buttons + / −, die auch Tastatur und Scrollen unterstützt.

3. Schwebende Labels

Das Label sitzt im Feld und wandert nach oben, sobald das Feld nicht leer ist. Das spart vertikalen Platz — bei einem Formular mit zwölf Feldern ist das ein Unterschied von einer ganzen Bildschirmhöhe beim Scrollen.

Der Mechanismus basiert auf der Frage „ist der Platzhalter sichtbar?". Die Pseudoklasse :placeholder-shown ist genau dann wahr, wenn das Feld leer ist — CSS hat keine andere Möglichkeit, das zu prüfen. Daher die beiden unüblichen Anforderungen unten. 

<div class="form-floating">
  <!-- placeholder=" " mit einem Leerzeichen — ohne das kehrt das Label nicht zurück -->
  <input type="text" class="input" id="name" placeholder=" ">
  <!-- label MUSS NACH dem Input stehen: CSS verbindet sie über einen Geschwister-Selektor -->
  <label for="name">Vor- und Nachname</label>
</div>
Anforderung Warum
Feld im Container .form-floating Gibt dem Label einen Bezugspunkt zur Positionierung.
placeholder=" " (mit Leerzeichen) Ein leerer placeholder="" zählt nicht als angezeigt, sodass das Label dauerhaft oben bliebe.
<label> nach dem Input Die Regel lautet .input:not(:placeholder-shown) ~ label. Der Geschwister-Selektor wirkt nur nach vorne — ein Label über dem Feld würde nie getroffen.

4. Validierung ohne JavaScript

Die gesamte Validierung stützt sich auf :user-invalid. Der Unterschied zum älteren :invalid ist grundlegend: :invalid ist bereits ab dem Laden der Seite wahr, sodass ein leeres Pflichtformular rot aufleuchtet, bevor der Nutzer überhaupt etwas getan hat. :user-invalid greift erst, nachdem der Nutzer das Feld betreten, falsche Daten eingegeben und es wieder verlassen hat. 

<div class="form-floating">
  <input type="email" class="input" id="email" placeholder=" " required>
  <label for="email">Geschäftliche E-Mail</label>

  <!-- Geschwister des Inputs. CSS zeigt sie selbst, wenn nötig -->
  <div class="feedback-invalid">Ungültige E-Mail-Adresse.</div>
</div>
Element Rolle
required, type, pattern Gewöhnliche HTML-Attribute. Sie definieren, was als Fehler gilt — dafür schreiben Sie keine Regeln.
.feedback-invalid Die Fehlermeldung. Standardmäßig verborgen; wird von der Regel .input:user-invalid ~ .feedback-invalid angezeigt, muss also ein Geschwister des Feldes sein und danach stehen.
Was ist mit Meldungen vom Server

:user-invalid behandelt ausschließlich Regeln, die der Browser kennt. Fehler vom Backend (Login bereits vergeben, ungültiger Rabattcode) rendern Sie weiterhin selbst — schreiben Sie einfach .feedback-invalid aus und geben Sie ihr Sichtbarkeit, da das Feld formal nicht ungültig ist.

5. Weitere Steuerelemente

Checkboxen und Radios

Native Steuerelemente sehen in jedem Browser anders aus, daher schaltet molique ihr Erscheinungsbild über appearance: none ab und zeichnet ein eigenes. Das Häkchen ist ein SVG-Icon, das als Data-URI in CSS eingebettet ist — keine zusätzlichen Dateien, keine Icon-Fonts. Das Tastaturverhalten bleibt nativ, da das Element darunter weiterhin ein gewöhnlicher <input> ist. 

<div class="form-check">
  <input class="form-check-input" type="checkbox" id="zustimmung">
  <label class="form-check-label" for="zustimmung">Ich akzeptiere die AGB</label>
</div>

Feldgruppen

Verklebt ein Feld mit Text, Icon oder Button zu einem glatten Rechteck — die inneren Ecken runden sich automatisch ab, unabhängig von der Reihenfolge der Elemente. 

<div class="input-group">
  <span class="input-group-text">https://</span>
  <input type="text" class="input" placeholder="seiten-adresse">
  <button class="btn btn-primary">Prüfen</button>
</div>

Dateiauswahl

Das native <input type="file"> lässt sich nicht stylen und sieht in jedem Browser anders aus. Die Komponente legt eine Drop-Zone darüber — das Feld selbst bleibt darin, sodass Bedienung, Datei-Drag-and-Drop und Barrierefreiheit weiterhin nativ funktionieren. 

<div class="file-upload">
  <input type="file" name="dokument">
  <div class="file-upload-icon">📄</div>
  <p class="file-upload-name">Datei hierher ziehen oder klicken</p>
</div>
Der Dateiname ersetzt sich selbst

Das automatisch geladene Modul js/modules/molique-file-upload.js lauscht auf das change-Ereignis am versteckten Feld — nach der Auswahl (per Klick oder Drag) überschreibt es den Inhalt von .file-upload-name mit dem Dateinamen. Das Element müssen Sie nicht manuell hinzufügen: Fehlt es im Markup, fügt das Modul es nach der ersten Dateiauswahl selbst ein.

Klasse Komponente Was sie macht
.form-check Checkbox / Radio Hülle: setzt Steuerelement und Beschreibung in eine Zeile.
.form-check-input Checkbox / Radio Das Steuerelement selbst. Derselbe Stil für checkbox und radio — die Form ergibt sich aus dem Typ.
.form-check-label Checkbox / Radio Die Beschreibung. Klickbar, vergrößert also das Berührungsziel.
.form-floating Schwebendes Label Feldcontainer mit Label im Inneren (Abschnitt 3).
.feedback-invalid Validierung Fehlermeldung (Abschnitt 4).
.input-group Feldgruppe Verklebt ein Feld mit Zusätzen zu einem Rechteck.
.input-group-text Feldgruppe Nicht klickbarer Zusatz: Einheit, Präfix, Icon.
.file-upload Dateiauswahl Drop-Zone rund um das native Feld.
.file-upload-animated Dateiauswahl Variante mit animiertem Rand, der auf Hover reagiert.
.file-upload-icon Dateiauswahl Icon in der Mitte der Zone.
.file-upload-name Dateiauswahl Beschriftung, die JS mit dem Namen der gewählten Datei überschreibt. Im Markup optional — ohne sie fügt das Modul sie selbst ein.

7. Fallstricke

1 Fehlendes placeholder=" "

Der häufigste Fehler auf dieser Seite und betrifft zwei Komponenten: schwebende Labels und das ausklappbare Textarea. Beide fragen CSS :placeholder-shown, also „ist das Feld leer?". Ohne Platzhalter lautet die Antwort immer „nein" — das Label bleibt oben, und das Textarea klappt nie zusammen. 

<!-- FALSCH - ein leerer Platzhalter zählt nicht als angezeigt -->
<input class="input" placeholder="">
<input class="input">

<!-- RICHTIG - ein Leerzeichen darin -->
<input class="input" placeholder=" ">
2 Label über statt unter dem Feld

Der Reflex schlägt vor, <label> vor <input> zu schreiben — so sieht ein normales Formular aus. Bei schwebenden Labels funktioniert das nicht: Die Regel nutzt den Geschwister-Selektor ~, der nur nach vorne wirkt. Visuell landet das Label trotzdem am richtigen Platz, da CSS es positioniert.

Dasselbe gilt für .feedback-invalid — eine Meldung vor dem Feld wird nie angezeigt.

3 Verwendung von :invalid statt :user-invalid

:invalid ist sofort nach dem Laden der Seite wahr, sodass ein Registrierungsformular den Nutzer mit einem vollständigen Satz roter Felder begrüßt, bevor dieser überhaupt geklickt hat. Das wirkt wie eine kaputte Seite. :user-invalid wartet auf Interaktion — und genau das nutzt molique.

4 Zu geringe Feldhöhe

Verlockend bei einem dichten CRM: height: 32px auf .input, dann passen mehr Zeilen hinein. Das verletzt das 44px-Berührungsziel, wodurch das Feld auf dem Smartphone mit dem Finger schwer zu treffen ist. Wenn Sie es wirklich enger brauchen, verwenden Sie .input-sm — es verringert das Padding, behält aber die untere Grenze bei.

Zmienne CSS

Cały wygląd molique — kolory, odstępy, typografia, dark mode — stoi na zmiennych CSS. Nie musisz nadpisywać żadnej reguły, żeby zmienić motyw: wystarczy podmienić wartości.

1. Jak to działa

Zmienna CSS to nazwane pudełko na wartość. Framework nigdy nie wpisuje koloru na sztywno — wszędzie sięga po zmienną. Gdy podmienisz jej zawartość, zmiana rozchodzi się natychmiast po wszystkich komponentach, które z niej korzystają.

Zmienne dziedziczą się w dół drzewa DOM — dokładnie tak jak kolor tekstu. Dlatego zasięg zmiany zależy wyłącznie od tego, na którym elemencie ją zadeklarujesz. To także powód, dla którego PurgeCSS nigdy nie może ich usuwać — patrz pułapka nr 3.

Kategoria Ile Gdzie zadeklarowane Kto ustawia
Zmienne motywu 89 :root w _root.scss Ty — globalnie, raz na projekt.
Zmienne komponentów 60 Plik danego komponentu Framework. Część możesz nadpisać w markupie.
Wejścia z markupu 6 Nigdzie — są tylko czytane Wyłącznie Ty. Bez nich komponent nie ma skąd wziąć danych.

2. Jak nadpisać wartość

Trzy zasięgi, od najszerszego do najwęższego. Wszystkie działają bez !important — nie walczysz ze specyficznością, tylko podajesz inną wartość.

Zasięg 1 Cały projekt

Własny arkusz podpięty po molique. To jest właściwy sposób na motyw marki. 

<link rel="stylesheet" href="css/molique-style.css">
<link rel="stylesheet" href="css/moj-motyw.css">   <!-- po molique -->
/* moj-motyw.css */
:root {
  --primary: #7C3AED;
  --primary-hover: #6D28D9;
  --primary-rgb: 124, 58, 237;   /* MUSI odpowiadać --primary */

  --border-radius: 4px;          /* ostrzejszy interfejs */
  --spacing-unit: 6px;           /* ciaśniejszy rytm w całym frameworku */
}

Zasięg 2 Jedna sekcja

Deklaracja na kontenerze obejmuje wszystko w środku. Przydatne, gdy jedna sekcja ma mieć inny akcent niż reszta strony. 

<section class="container p-5" style="--primary: #059669;">
  <!-- każdy .btn-primary i .text-primary tutaj jest zielony -->
  <button class="btn-primary">Zapisz</button>
</section>

Zasięg 3 Pojedynczy element

Tak przekazujesz dane z backendu — postęp, ocenę, poziom zapasu. Wartość liczbowa jedzie w zmiennej, a nie w klasie, bo klas nie wolno sklejać dynamicznie. 

<div class="star-rating" style="--rating: 4.5;"></div>
<div class="stock-bar stock-bar-warning" style="--stock-filled: 2;"></div>
<div class="chart-radial" style="--val: 75%;"></div>

3. Dark mode

Ciemny motyw to wyłącznie inny zestaw wartości — zero dodatkowych reguł i zero duplikatów komponentów. Atrybut data-theme="dark" na <html> podmienia 31 z 89 zmiennych motywu.

Dlatego dodając własną zmienną kolorystyczną, musisz podać ją w obu blokach. Zmienna zadeklarowana tylko w :root zostanie w dark mode taka sama i najpewniej zniknie na ciemnym tle. 

:root {
  --marka-akcent: #B45309;
}

[data-theme="dark"] {
  --marka-akcent: #FBBF24;   /* jaśniejszy, żeby był czytelny na ciemnym */
}
Skąd się bierze motyw systemowy

Oba bloki deklarują też color-scheme. To ono sprawia, że natywne kontrolki — scrollbary, kalendarz w input[type="date"], tło <dialog> — podążają za motywem. Bez tej deklaracji nagłówki w modalu potrafią zrobić się czarne na ciemnej karcie.

4. Cztery pułapki

Każda z nich kosztowała już czyjeś popołudnie. Wszystkie wynikają z tego samego: zmienna nie mówi, czym jest — trzeba to wiedzieć.

1 --dark nie znaczy „ciemny"

W motywie jasnym --dark to #1E293B (grafit), ale w dark mode odwraca się na #F8FAFC (biel). To nie jest „kolor ciemny" — to kolor kontrastowy do tła. Tak samo --light w dark mode staje się ciemny.

Skutek: użyty na elemencie leżącym na zdjęciu — którego tło nie zmienia się z motywem — daje biały tekst na białym tle. 

/* ŹLE - na zdjęciu tekst zniknie w dark mode */
.podpis-na-zdjeciu { color: var(--dark); }

/* DOBRZE - literalna wartość, niezależna od motywu */
.podpis-na-zdjeciu { color: #1E293B; }
2 --x i --x-rgb to nie to samo

--primary to gotowy kolor. --primary-rgb to same kanały (2, 132, 199) — bez tego nie da się zrobić przezroczystości. Działa wyłącznie wewnątrz rgba().

Wpisana gdziekolwiek indziej nie jest poprawnym kolorem, więc przeglądarka odrzuca całą deklarację — po cichu, bez błędu w konsoli. 

/* ŹLE - "2, 132, 199" nie jest kolorem, deklaracja przepada */
.karta { border-color: var(--primary-rgb); }

/* DOBRZE */
.karta { border-color: var(--primary); }
.karta { background: rgba(var(--primary-rgb), 0.1); }

Zmieniając --primary w swoim motywie, zawsze zmieniaj też --primary-rgb. Rozjazd tej pary daje przezroczystości w starym kolorze.

3 PurgeCSS z variables: true kasuje motyw

Ta opcja usuwa zmienne CSS, których PurgeCSS nie znalazł w Twoich plikach. Problem w tym, że zmienne molique są używane wewnątrz reguł frameworka, a nie w Twoim HTML-u — więc narzędzie uznaje je za martwe i wycina. Efekt: strona bez kolorów i odstępów. 

// purgecss.config.js
module.exports = {
  variables: false,   // ZOSTAW false - na zmiennych stoi cały motyw
};

Szczegóły i gotowa konfiguracja: PurgeCSS & safelista.

4 Sidebar admina jest ciemny zawsze

--sidebar-bg celowo nie ma odpowiednika w dark mode — panel boczny wygląda tak samo w obu motywach. Dlatego jego jasne akcenty muszą być literalne.

Użycie tam --light-rgb wygląda poprawnie w motywie jasnym, ale w ciemnym ta zmienna odwraca się na ciemną — i tekst oraz podświetlenia znikają na ciemnym tle sidebara. Od tego jest osobna --sidebar-highlight-rgb. 

/* ŹLE - w dark mode hover zniknie */
.admin-nav-link:hover { background: rgba(var(--light-rgb), 0.1); }

/* DOBRZE - akcent niezależny od motywu */
.admin-nav-link:hover { background: rgba(var(--sidebar-highlight-rgb), 0.1); }

5. Zmienne motywu 89

Zadeklarowane w :root. Kolumna Dark mode pokazuje wartość po włączeniu ciemnego motywu — bez zmian oznacza, że zmienna jest wspólna dla obu motywów. Kolumna Używana w wskazuje moduły SCSS, które z niej korzystają.

6. Zmienne komponentów 60

Deklarowane wewnątrz konkretnego komponentu, więc działają tylko w jego obrębie. Dwa rodzaje:

  • markup — przewidziane do nadpisania przez Ciebie, zwykle przez style="--x: …".
  • wewnętrzna — framework liczy je sam. Wypisane, bo widać je w DevTools i warto wiedzieć, że to nie miejsce na Twoje zmiany.

7. Wejścia z markupu 6

Zmienne, których framework nigdy nie deklaruje — tylko je czyta. To interfejs do przekazywania danych z backendu. Jeśli w kolumnie Gdy nie ustawisz widnieje wymagana, brak wartości oznacza, że komponent nie wyrenderuje się poprawnie.

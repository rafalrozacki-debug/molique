Buttons & Badges

Ein Button setzt sich aus drei unabhängigen Entscheidungen zusammen: Farbe, Größe, Erscheinungsbild. Diese Seite listet alle Optionen auf und erklärt, wann es erlaubt ist, die 44px-Regel zu brechen. Fertige Zusammenstellungen finden Sie in den Beispielen.

1. Anatomie

Form, 44px Höhe und Fokusring stammen von der Basis .btn — aber eine Farbklasse impliziert sie selbst, sodass .btn-primary ausreicht. Der Rest sind Modifikatoren, die kombiniert werden können, aber jeweils nur einer pro Gruppe. 

<button class="btn-primary">Speichern</button>
<button class="btn-primary btn-lg">Größer</button>
<button class="btn-outline-primary btn-sm">Umriss, kleiner</button>

<!-- Funktioniert auf jedem Element -->
<a href="/preise" class="btn-secondary">Preise ansehen</a>

<!-- .btn allein wird weiterhin benötigt, wenn Sie keine Farbe angeben -->
<button class="btn">Neutral</button>

Was die Implikation nicht abdeckt

Die Basis tragen ausschließlich die Farb-Klassen (.btn-primary … .btn-dark) und ihre Umriss-Varianten. Größen-Modifikatoren (.btn-lg) und Erscheinungs-Modifikatoren (.btn-3d, .btn-glass) sind Ergänzungen — für sich genommen erzeugen sie keinen Button. Ein Sonderfall ist .btn-action, das die Basis bewusst nicht erbt, da es die 44px-Regel bricht.

Farben

Klasse Wann
.btn-primary Die Hauptaktion des Bildschirms. Eine pro Ansicht.
.btn-secondary Eine Nebenaktion: Abbrechen, Zurück.
.btn-success Bestätigung, Abschluss eines Prozesses.
.btn-danger Eine unumkehrbare Aktion: Löschen, Vertrag kündigen.
.btn-warning Eine Aktion, die Aufmerksamkeit erfordert.
.btn-info Eine neutrale, informative Aktion.

2. Erscheinungsvarianten

Sie ändern, wie ein Button gezeichnet wird, nicht seine Bedeutung. Die Umriss-Variante hat eine Version für jede Farbe; der Rest funktioniert bei allen.

Klasse Aussehen
.btn-outline-primary Nur der Rahmen, der Hintergrund füllt sich erst bei Hover. Die Variante existiert für jede Farbe: .btn-outline-secondary, .btn-outline-success, .btn-outline-danger, .btn-outline-warning, .btn-outline-info, .btn-outline-dark, .btn-outline-light.
.btn-outline-soft Ein abgemilderter Umriss: Rahmen mit 30 % Deckkraft, Hintergrund bei Hover 10 %. Fügen Sie sie zur Umriss-Variante hinzu.
.btn-3d Ein „Sockel"-Schatten, der beim Klicken hineingedrückt wird. Die Sockelfarbe steckt in --btn-3d-shadow — setzen Sie sie selbst, wenn Sie eine andere Farbe als primary verwenden.
.btn-glass Mattiertes Glas. Nur auf einem Foto oder Verlauf — auf einem einfarbigen Hintergrund gibt es nichts zu verwischen. Siehe Fallstrick Nr. 2.
.btn-glow Ein bei Hover anwachsender Schimmer.
.btn-gradient Ein Hintergrund mit Verlauf primary → info. Ignoriert die Farbklasse.
.btn-shine Ein Lichtreflex, der über den Button läuft.
.btn-stacked Icon über statt neben der Beschriftung — eine Werkzeugleiste, die untere Navigation einer App.
.btn-text Die Beschriftung innerhalb von .btn-stacked — klein, in Großbuchstaben. Keine eigene Button-Variante. 
<button class="btn btn-outline-primary btn-outline-soft">Zarter Umriss</button>

<button class="btn btn-primary btn-stacked">
  <svg>…</svg>
  <span class="btn-text">Speichern</span>
</button>

3. Hover-Effekt

Statt jeden Button einzeln zu markieren, wählen Sie den Effekt einmal für den gesamten Bereich — per Klasse auf <body> oder auf einem Container. Alle .btn darin erben ihn. 

<body class="btn-hover-spring">
  <button class="btn btn-primary">Erbt die Feder</button>

  <!-- Eine eigene hover-*-Klasse hat Vorrang -->
  <button class="btn btn-primary hover-scale">Skaliert stattdessen</button>
</body>
Klasse Effekt
.btn-hover-spring Vergrößerung mit federndem Ausschwingen.
.btn-hover-lift Anheben nach oben.
.btn-hover-glow Ein Schimmer um den Button.

Wie der Vorrang funktioniert

Die Regel zielt auf .btn:not([class*="hover-"]), überspringt also Buttons, die bereits eine eigene hover--Klasse haben. Dadurch erzeugen Sie eine Ausnahme durch Hinzufügen einer Klasse, nicht durch einen Kampf mit der Spezifität. Der Effekt lässt sich auch im Theme-Editor auswählen.

Effekte außerhalb des Buttons-Moduls

Die hover-*-Klassen aus dem Utility-Modul sind an keine Komponente gebunden — sie funktionieren auf jedem Element, also auch auf einem Button. Unten die, die dort sinnvoll sind, samt dem, was sie erfordern. Vollständige Galerien: Mikrointeraktionen und Rahmeneffekte.

Klasse Effekt Am Button
.hover-scale Vergrößerung. Stärke bestimmt --hover-scale. unbedenklich
.hover-shadow Anheben mit Schatten. Höhe: --hover-y. unbedenklich
.hover-gpu-shadow Ein wachsender Schatten, ohne box-shadow zu animieren. unbedenklich
.hover-tilt Eine feste 3D-Neigung. unbedenklich
.hover-border-draw Ein von innen nach außen gezeichneter, abgerundeter Rahmen. unbedenklich Zeichnet in einem eigenen ::before, rührt also nicht den Hintergrund des Buttons an.
.hover-border-trace Ein den Umriss umlaufendes Licht, abgerundet. unbedenklich Ebenfalls ::before.
.hover-border-draw-2 Ein Seite für Seite gezeichneter Rahmen, scharfe Ecken. Farbe setzen Siehe Hinweis unter der Tabelle.
.hover-border-trace-2 Ein Seite für Seite umlaufender Umriss, scharfe Ecken. Farbe setzen Siehe Hinweis unter der Tabelle.
.tilt-card Eine dem Cursor folgende Neigung. benötigt JS Schaltet sich bei Touch-Bedienung selbst ab.
.bg-hover-*, .text-hover-*, .border-hover-* Farbwechsel bei Hover. nicht empfohlen Ein Button hat bereits eine eigene Hover-Farbe aus seiner Variante — diese Klassen konkurrieren damit. Ändern Sie stattdessen --primary-hover, statt die Utility hinzuzufügen.

Warum die -2-Varianten eine Farbe benötigen

Die Varianten mit scharfen Ecken zeichnen kein Pseudo-Element — die Linien sind vier Verläufe im background-image des Elements selbst. Der Hintergrund des Buttons (background-color) bleibt unberührt, sie funktionieren also technisch. Das Problem ist visueller Natur: Die Linie hat standardmäßig die Farbe --primary, ist also auf einem .btn-primary unsichtbar. 

<button class="btn btn-primary hover-border-draw-2"
        style="--hover-border-color: #fff;">Weißer Rahmen</button>

4. Aktions-Buttons und Gruppen

Ghost Buttons

.btn-action ist der einzige Button in molique, der bewusst unter 44px bleibt. Der Grund ist praktisch: In einer Tabelle mit Dutzenden Zeilen sprengen vollformatige Buttons die Zeilen so weit auf, dass nur fünf auf den Bildschirm passen. Das ist eine für dichte Aufstellungen erlaubte Ausnahme — kein gewöhnlicher Button. 

<div class="btn-action-group with-dividers">
  <button class="btn-action">Bearbeiten</button>
  <button class="btn-action text-danger">Löschen</button>
</div>

Button-Gruppen

Verkleben eine Reihe von Buttons zu einer Leiste — ein Ansichts-Umschalter, eine Werkzeugleiste. Die inneren Ecken runden sich von selbst ab. Markieren Sie die aktuelle Position mit .is-active. 

<div class="btn-group">
  <button class="btn btn-outline-dark is-active">Liste</button>
  <button class="btn btn-outline-dark">Kacheln</button>
</div>
Klasse Was sie macht
.btn-action Ein Button ohne Hintergrund und Rahmen für dichte Tabellen.
.btn-action-group Stellt die Aktionen einer Zeile nebeneinander zusammen.
.with-dividers Fügt vertikale Trennstriche zwischen den Aktionen ein. Nur mit .btn-action-group.
.btn-group Eine Leiste verklebter Buttons.
.is-active Die gedrückte Position in einer Gruppe.

5. Badges

Eine Statuspille — eine nicht klickbare Beschriftung neben einem Datensatz. Mit der Farbe kommunizieren Sie einen Zustand, verzieren nicht: ein rotes Badge bei jeder Zeile hört auf, irgendetwas zu bedeuten.

Primary Aktiv Ausstehend Überfällig Info Entwurf Archiv
Klasse Typische Verwendung
.badge Die Basis — Form, Größe, Abstände.
.badge-primary Neutrale Hervorhebung.
.badge-success Aktiv, bezahlt, abgeschlossen.
.badge-warning Ausstehend, erfordert Aufmerksamkeit.
.badge-danger Überfällig, abgelehnt, Fehler.
.badge-info Ein Vermerk, eine Zwischenstufe.
.badge-secondary Entwurf, unbedeutender Zustand.
.badge-dark Archiv, geschlossen.

Wann statt eines Badges ein Punkt verwendet wird

Wenn es pro Zeile einen Status gibt und dieser keine Beschriftung braucht, nimmt .status-dot weniger Platz ein und konkurriert visuell nicht mit dem Inhalt. Beschrieben in den zusätzlichen Komponenten.

6. Fallstricke

1 .btn-action außerhalb einer Tabelle

Dieser Button sieht aufgeräumt aus, daher ist es verlockend, ihn überall zu verwenden. Er ist aber eine bewusste Ausnahme von der 44px-Regel — nur deshalb erlaubt, weil in einer dichten Tabelle die Alternative schlechter ist. In einem Formular oder auf einer Angebotsseite verletzt er schlicht das Berührungsziel: Auf dem Smartphone ist er mit dem Finger schwer zu treffen.

2 .btn-glass auf einfarbigem Hintergrund

Der Glaseffekt beruht darauf, das zu verwischen, was sich unter dem Button befindet. Auf einem einfarbigen Hintergrund gibt es nichts zu verwischen — es bleibt ein kaum sichtbares Rechteck übrig. Diese Variante ergibt nur auf einem Foto, einem Verlauf oder animierten Farbflecken Sinn.

Zusätzlich sind ihr Hintergrund und Rahmen mit !important festgelegt, um gegen die Farbklasse zu gewinnen — Sie können sie also nicht mit einer gewöhnlichen Hintergrundklasse überschreiben. Ändern Sie sie per Inline-Style am Element, oder verwenden Sie diese Variante nicht.

3 .btn-3d in einer anderen Farbe als primary

Die „Sockel"-Farbe unter dem Button ist --btn-3d-shadow, standardmäßig --primary-hover. Ein grüner Button erhält also einen violetten Sockel und wirkt kaputt. Setzen Sie die Variable zusammen mit der Farbe. 

<button class="btn btn-success btn-3d"
        style="--btn-3d-shadow: var(--success-hover);">Speichern</button>
4 Ein aus dem Status vom Backend zusammengesetzter Klassenname

Ein gängiger Reflex beim Generieren einer Tabelle: class="badge badge-<?= $status ?>". Ein solcher Name kommt im Quellcode nie als Literal vor, daher sieht ihn PurgeCSS nicht und entfernt ihn — nach dem Deployment sind alle Status farblos. Bilden Sie den Status auf ein Literal ab, oder fügen Sie das Muster zur Safelist hinzu. 

// FALSCH
'badge badge-' + status

// RICHTIG - eine Literal-Map, validiert nebenbei die Eingabe
const BADGE = { active: 'badge-success', pending: 'badge-warning' };
BADGE[status] || 'badge-secondary';
5 Mehrere .btn-primary-Buttons nebeneinander

Das ist kein technischer Fehler, sondern ein Informationsverlust. Primary bedeutet „das ist wahrscheinlich die Aktion, die Sie ausführen möchten". Drei solche Buttons an einer Stelle sagen gar nichts. Lassen Sie einen davon, machen Sie den Rest zu .btn-secondary oder Umriss-Buttons.

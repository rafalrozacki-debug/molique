Durchsuchbares Select & Schalter

Zwei Selects auf Basis der Popover API — eine Einfachauswahl mit Suche und eine Mehrfachauswahl mit Tags — sowie Schalter im iOS-Stil. Fertige Showcases: Select und Schalter.

1. Warum die Popover API

Ein natives <select> hat weder Suche noch Mehrfachauswahl mit Tags. Statt es komplett in JavaScript nachzubauen, stehen beide Komponenten auf dem Attribut popover: Das aufklappbare Menü landet im Top Layer — einer eigenen Browser-Ebene über dem gesamten Rest der Seite.

Effekt: Das Menü wird nie abgeschnitten

Ein Menü in einer scrollenden Tabelle, in einem Modal, in einer Karte mit overflow: hidden — an jeder dieser Stellen würde ein gewöhnliches position: absolute vom übergeordneten Element abgeschnitten. Der Top Layer liegt außerhalb dieser Hierarchie, daher liegt das Menü immer obenauf, und die Verankerung am Button erfolgt automatisch (impliziter Anchor).

2. Select mit Suche

Einfachauswahl aus einer Liste. Die Suche ist optional — ohne Textfeld verhält sich die Komponente wie ein gewöhnliches Select, nur mit ihrem Menü im Top Layer. 

<div class="select-search">
  <button type="button" class="input select-search-trigger"
          popovertarget="kunde-select">
    <span>Aus der Liste wählen…</span>
  </button>

  <div class="select-search-menu" popover id="kunde-select">
    <input type="text" class="input select-search-input"
           placeholder="Suchen…">
    <div class="select-search-list">
      <div class="select-search-option" data-value="1">Molique</div>
      <div class="select-search-option" data-value="2">Briko</div>
    </div>
  </div>
</div>
Klasse / Attribut Was sie tut
.select-search Die Hülle. Impliziter Anchor für das Menü.
.select-search-trigger Der öffnende Button. Benötigt popovertarget, das auf die id des Menüs zeigt.
.select-search-menu Das Panel. Benötigt das Attribut popover und eine eindeutige id — ohne sie landet es nicht im Top Layer und verschwindet wie ein gewöhnliches <div>.
.select-search-input Das Suchfeld. Optional.
.select-search-list Der Container für die Optionen.
.select-search-option Eine einzelne Option. Benötigt data-value — von dort liest das Modul den Wert bei der Auswahl.
.is-selected Die aktuell gewählte Option. Vom Skript gesetzt.
.is-hidden Eine durch die Suche ausgefilterte Option. Ebenfalls vom Skript.

Event-Delegation — funktioniert mit AJAX

Das Modul lauscht am Container, nicht an einzelnen Optionen, und behandelt daher auch .select-search-option, die nach dem Seitenstart in das DOM nachgeladen werden — z. B. das Ergebnis einer AJAX-Anfrage. Nichts muss neu initialisiert werden.

Wert aus JavaScript setzen

Für die programmatische Befüllung (z. B. Öffnen eines Bearbeitungsformulars mit Datensatzdaten) gibt es eine globale Funktion — sie synchronisiert Beschriftung am Button und Hervorhebung genauso wie eine Auswahl per Maus. 

const hidden = document.querySelector('#kunde-id');
MoliqueSelectSearch.setValue(hidden, '2');

3. Multi-Select

Mehrfachauswahl mit Tags am Button. Die Struktur der Optionen ist ein gewöhnliches <label> mit Checkbox — das Auswählen funktioniert also nativ, ohne Logik in JS. 

<div class="custom-select">
  <button type="button" class="custom-select-trigger"
          popovertarget="skills-select">
    <div class="custom-select-pills">…</div>
  </button>

  <div class="custom-select-dropdown" popover id="skills-select">
    <div class="custom-select-search">
      <input type="text" class="input" placeholder="Suchen…">
    </div>
    <div class="custom-select-list">
      <div class="custom-select-category">Backend</div>
      <label class="custom-select-option">
        <div class="flex-1">PHP</div>
        <input type="checkbox" class="form-check-input">
      </label>
    </div>
  </div>
</div>
Klasse Was sie tut
.custom-select Die Hülle.
.custom-select-trigger Der Button. Enthält .custom-select-pills statt einer einzelnen Beschriftung.
.custom-select-pills Eine Reihe von Tags der gewählten Optionen, in .badge gehüllt.
.custom-select-dropdown Das Panel. Benötigt popover und id — genau wie beim Einfach-Select.
.custom-select-search Der Container des Suchfelds.
.custom-select-list Der Container für Kategorien und Optionen.
.custom-select-category Eine Überschrift, die Optionen gruppiert.
.custom-select-option Auf einem <label>. Darin ein gewöhnliches input[type="checkbox"].form-check-input.
.icon-chevron Der Pfeil am Button; dreht sich beim Öffnen um 180°.
.search-icon Das Lupen-Icon im Suchfeld.

4. Schalter

Eine Checkbox, verkleidet als Schieberegler im iOS-Stil. Der gesamte Mechanismus besteht aus appearance: none auf der Checkbox und einem Pseudo-Element als schwebendem Knopf — null JavaScript, null zusätzliche Elemente im DOM. 

<label class="form-switch">
  <input type="checkbox" class="form-switch-input" checked>
  <span class="form-switch-label">E-Mail-Benachrichtigungen</span>
</label>
Klasse Was sie tut
.form-switch Auf einem <label>. Ein Klick an beliebiger Stelle — auch auf den Text — schaltet den Zustand um.
.form-switch-input Die Checkbox selbst, umgestylt zu einem 44×24px-Schieberegler. Die Farbe im aktivierten Zustand ist immer --success — siehe Fallstrick Nr. 3.
.form-switch-label Die Beschriftung neben dem Schieberegler.
.form-switch-square Eine Variante mit eckigen statt runden Ecken.
.form-switch-outline Eine Variante mit nur einer Umrandung statt gefülltem Hintergrund — visuell weniger dominant.

Schalter als Collapse-Auslöser

Ein .form-switch, direkt vor .grid-expand platziert (als Geschwisterelement), zeigt beim Aktivieren den Inhalt darunter — null JS. Vollständige Beschreibung des Mechanismus und ein struktureller Fallstrick in der Dokumentation zu interaktiven Komponenten.

5. Fallstricke

1 Fehlendes popover oder id am Panel

Ohne das Attribut popover ist das Panel ein gewöhnliches <div> — der Button mit popovertarget hat nichts zu öffnen, der Klick tut also nichts. Ohne passende id zeigt der Button ins Leere. Beide Fälle sehen identisch aus: Das Menü erscheint einfach nicht, ohne Konsolenfehler. 

<!-- FALSCH - kein popover, der Button öffnet nichts -->
<div class="select-search-menu" id="x">…</div>

<!-- RICHTIG -->
<div class="select-search-menu" popover id="x">…</div>
2 Fehlendes data-value an einer Option

Das Modul liest den Wert einer Option ausschließlich aus dem Attribut data-value, nicht aus dem Inhalt des Elements. Eine Option ohne dieses Attribut lässt sich visuell auswählen — sie wird hervorgehoben und die Beschriftung eingefügt —, aber das versteckte Feld bleibt leer, das Formular sendet also keinen Wert.

3 Die Schalterfarbe ist fest auf Grün eingestellt

Ein aktivierter .form-switch-input nimmt immer --success an — es gibt keinen Farb-Modifikator und keine lokale Variable zum Überschreiben pro Instanz. Brauchen Sie eine andere Farbe (z. B. einen roten „Daten löschen"-Schalter), führt der einzige Weg über eine eigene CSS-Regel, die genau diese Klasse anvisiert — denn eine globale Änderung von --success würde auch jede andere Verwendung dieser Farbe im Projekt ändern.

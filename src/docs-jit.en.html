molique JIT & CLI

An engine that generates only the CSS you actually use — no PurgeCSS, no safelist, no guessing. Plus a command-line tool with a live watch mode and a generator for ready-made HTML blocks.

This is a preview — the package isn't on npm yet

The JIT engine and CLI described on this page exist, work, and have been manually verified — this isn't a preview of a feature that doesn't exist yet. The only thing genuinely missing is the first publish of the molique-jit package to the npm registry, so npx molique-jit won't work out of the box just yet.

Until then, the fastest way to try it is to build the package locally from source — see Installing from source below. The source code is public in the repository: github.com/rafalrozacki-debug/molique.

1. How this differs from PurgeCSS

The PurgeCSS & safelist page describes a "big to small" approach — you take the full, compiled molique CSS and cut out anything not found in your files. It works, but it needs a safelist (because some classes are only added by JavaScript) and carries risk: if PurgeCSS misses something and you forget the safelist, a component silently stops working.

molique-jit works the other way around: it starts from nothing and adds only the classes it actually found as literal text in your HTML/JS files. It never deletes anything, so there's nothing to "forget" in a safelist — classes triggered by JavaScript (toasts, lightbox, .is-* states) are built into the engine as always-included, exactly like in the ready-made PurgeCSS safelist.

PurgeCSS (available today) molique-jit (preview)
Starting point The full compiled molique-style.css Nothing — only adds matched classes
Needs a safelist Yes, wired in manually (purgecss.safelist.cjs) No — runtime classes are built into the engine
Live watch mode Needs its own wiring (e.g. a PostCSS plugin) Built in: watch
HTML component generator None make:component (see section 6)

You don't have to pick one forever

Both paths solve the same problem (a smaller production CSS file) in different ways. Once molique-jit lands on npm, it'll be a simpler, zero-config alternative to PurgeCSS for new projects — the PurgeCSS page stays for anyone who'd rather plug it into an existing build pipeline.

2. How it works (in short)

molique's utility classes (.pb-md-4, .text-hover-primary, etc.) aren't arbitrary — they form a finite, fully known set, computed once when the framework is compiled. That's why the JIT engine never calculates CSS on the fly — instead it works like a dictionary:

1

Scans

Reads your files (HTML, JS, PHP — whatever you point it at via content) and pulls out every token that looks like a class name.

2

Matches

Checks every token against a ready-made dictionary of molique classes (a lookup, not a calculation). A token outside the dictionary is just your own class — not an error.

3

Copies

Outputs ready CSS rules 1:1 from the real, compiled framework, preserving @layer ordering.

The result: the output file is byte-for-byte identical to what the full molique-style.css would give you for the same classes — the engine never invents or recalculates anything on its own.

3. Installing from source (until it's on npm)

Requires Node.js. Clone the repository and build the package locally: 

git clone https://github.com/rafalrozacki-debug/molique.git
cd molique/tools/jit/package
npm install
npm run build

From here, node dist/cli.js behaves exactly like npx molique-jit in the rest of this documentation — just swap one for the other: 

node dist/cli.js init
node dist/cli.js build --minify
node dist/cli.js make:component

This section will disappear once the package is published, and every npx molique-jit … example below will work without any syntax change — the CLI is already written for its intended usage.

4. The molique.config.mjs file

The init command creates this file for you, with comments on every field. A full, hand-written example: 

// molique.config.mjs
export default {
  // Where to look for class names.
  content: ['**/*.html', '**/*.php'],

  // Where to write the resulting CSS.
  output: 'css/molique-jit.css',

  // ONLY classes specific to your project (e.g. composed in PHP).
  // molique's own runtime classes (toasts, carousel, .is-* states) don't
  // need to be listed here — the engine includes them automatically.
  safelist: ['badge-success', 'badge-danger'],
};

If your project has several independent pages (e.g. a main site and a separate campaign landing page), the targets field replaces content/output above and builds each target independently — the landing page gets its own small CSS file, with nothing else in it: 

export default {
  targets: [
    { content: ['src/**/*.html'], output: 'css/molique-jit.css' },
    { content: ['landing-campaign.html'], output: 'css/landing-campaign.css' },
  ],
};
Field Default Description
content ['**/*.html', '**/*.php'] Where to look for classes (glob patterns).
output css/molique-jit.css Path of the output file.
safelist [] Classes from your own project the scan might miss (e.g. composed on the backend).
minify false Currently effectively a no-op — the source data is already compressed at the source.
targets — A list of independent builds; when present, replaces content/output.

5. CLI commands

The binary is called molique-jit (not just molique), to avoid colliding with other tools that use a shorter name. The CLI understands commands in English, but also their Polish and German equivalents — handy for teams that work day-to-day in one of those languages.

English (canonical) Polish alias German alias What it does
init start start Creates a molique.config.mjs file with a sample config.
build buduj bauen Compiles CSS to the output file(s) once.
watch obserwuj beobachten Watches files and rebuilds live (~50ms debounce).
--minify / -m --minifikuj --minifizieren Forces output compression.
--config / -c --konfiguracja --konfiguration Points to a custom config file path.

All three language variants do exactly the same thing:

npx molique-jit init
npx molique-jit build --minify
npx molique-jit watch --config ./custom.config.mjs
npx molique-jit start
npx molique-jit buduj --minifikuj
npx molique-jit obserwuj --konfiguracja ./custom.config.mjs
npx molique-jit start
npx molique-jit bauen --minifizieren
npx molique-jit beobachten --konfiguration ./custom.config.mjs

Exit codes

build exits with 0 on success and 1 on error (e.g. the config points to a folder that doesn't exist) — handy to wire into CI, e.g. as a step before publishing.

6. Component generator: make:component

A separate command, independent of building CSS. It runs an interactive wizard in the terminal (arrow keys + Enter) and prints a ready, paste-in HTML block at the end — matching, character for character, the real, working modal examples in this documentation.

Current state: the first iteration of the generator supports only Modal (a native <dialog>), in the three variants described below. A B2B table generator and full-page templates (described as an idea in the Roadmap) aren't implemented yet — don't rely on them until they show up here. 

npx molique-jit make:component

The wizard asks, in order, for:

Standard

A plain modal: title, body text, trigger button (label + color).

Confirm

A confirmation dialog: question, description, Cancel/Confirm button labels, action color (e.g. danger for deletions) and a warning icon.

Context

A side context menu: title plus the first two action items (label + icon) — add more by hand, copying the generated pattern.

At the end you choose whether the code goes straight to the console (to copy with your mouse) or gets saved to a file — the tool never overwrites an existing file without an explicit confirmation.

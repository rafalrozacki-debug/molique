Onboarding

Dwa niezależne, w pełni opcjonalne komponenty do wdrażania nowych użytkowników - żaden z nich nie wymaga drugiego. Oba działają na natywnym <dialog> (showModal()), więc fokus-trap, przywracanie fokusu i zamykanie klawiszem Esc dostajesz za darmo, bez własnego kodu.

1. Co wybrać

Komponent Kiedy Definiowanie treści
.onboarding-dialog Pierwsze wejście do panelu - krótkie "co to za produkt", zanim użytkownik zobaczy interfejs. data-onboarding-* LUB MoliqueOnboarding.start()
.tour-dialog Użytkownik już widzi interfejs - trzeba mu pokazać, gdzie jest konkretna funkcja. data-tour na realnych elementach LUB MoliqueTour.start()

Łączenie obu w jeden ciąg

Oba API zwracają Promise, rozwiązywany po zamknięciu (Pomiń, Escape albo ukończenie ostatniego kroku) - można więc uruchomić Tour zaraz po planszach: 

MoliqueOnboarding.start(slides).then(() => MoliqueTour.start(steps));

2. Onboarding Slides

Pełnoekranowe plansze powitalne: ikona lub obrazek + tytuł + opis, z przyciskami Dalej/Wstecz/Pomiń i kropkami postępu. W trybie deklaratywnym pokazują się automatycznie raz na przeglądarkę (localStorage) - integrator nie pisze ani linijki JS. 

<!-- Wariant deklaratywny (zero JS) -->
<div data-onboarding hidden>
  <div data-onboarding-slide
       data-onboarding-icon="ph-hand-waving"
       data-onboarding-title="Witaj w panelu"
       data-onboarding-desc="Krótki opis pierwszego kroku."></div>
  <div data-onboarding-slide
       data-onboarding-image="img/onboarding/zamowienia.png"
       data-onboarding-image-alt="Zrzut ekranu listy zamówień"
       data-onboarding-title="Zamówienia"
       data-onboarding-desc="Tu zarządzasz zamówieniami."></div>
</div>

<!-- Wariant JS (treść dynamiczna) -->
<script>
  MoliqueOnboarding.start([
    { icon: 'ph-hand-waving', title: 'Witaj w panelu', description: '…' },
    { image: 'zamowienia.png', imageAlt: '…', title: 'Zamówienia', description: '…' },
  ], {
    onSkip: () => {},
    onComplete: () => {},
  });
</script>
Klasa / atrybut Co robi
.onboarding-dialog Natywny <dialog> budowany przez JS - nie piszesz go ręcznie.
data-onboarding Owija slajdy. Opcjonalnie data-onboarding-key="nazwa" - własny klucz zapisu w localStorage (domyślnie ścieżka strony).
data-onboarding-slide Jeden slajd. Kolejność = kolejność w DOM. Atrybuty: data-onboarding-icon (fragment sprite'a ikon, np. ph-hand-waving) LUB data-onboarding-image + data-onboarding-image-alt (wzajemnie wykluczające się), data-onboarding-title, data-onboarding-desc.
MoliqueOnboarding.start(slides, options) slides: tablica obiektów jak wyżej. options.onSkip / options.onComplete. Zwraca Promise.

3. Spotlight Tour

Sekwencja kroków po realnych elementach interfejsu: reszta ekranu ciemnieje, podświetlony element zostaje widoczny, ale nieklikalny - showModal() robi całe poddrzewo strony poza dialogiem naprawdę inert (specyfikacja przeglądarki, nie sztuczka na pointer-events). Sterują wyłącznie przyciski Dalej/Wstecz/Pomiń w dymku.

Klasa / atrybut Co robi
.tour-dialog Natywny <dialog> budowany przez JS.
.tour-spotlight "Dziura" w przyciemnieniu - pozycja/rozmiar liczone z getBoundingClientRect() celu na każdym kroku (klasyczna technika box-shadow: 0 0 0 9999px, nie maska SVG).
.tour-tooltip Dymek z tytułem/opisem, pozycjonowany przez natywny CSS Anchor Positioning (anchor-name ustawiany z JS na celu + 5-kierunkowy łańcuch @position-try, żeby nigdy nie wypadł poza ekran).
data-tour Oznacza realny element jako krok tury. Opcjonalnie data-tour-group="nazwa" (domyślnie "default") - kilka niezależnych tur na jednej stronie.
data-tour-title / data-tour-desc Treść dymku dla danego kroku. Kolejność kroków = kolejność elementów w DOM (jak grupy data-gallery w Lightboksie) - brak osobnego atrybutu z numerem.
MoliqueTour.start(steps, options) steps: tablica { target, title, description } (target - selektor LUB żywy element). options.onStepChange / onSkip / onComplete. Zwraca Promise.

4. Pułapki i świadome ograniczenia

1 Elementy dodawane do strony PO wczytaniu

Skan deklaratywny ([data-tour] / [data-onboarding]) dzieje się RAZ, przy starcie modułu - jak w Lightboksie, bez MutationObserver. Panel renderowany po czasie (spinner, hydratacja) wymaga MoliqueTour.start() / MoliqueOnboarding.start() z JS zamiast samych atrybutów.

2 Brak strzałki wskazującej kierunek przy dymku

Świadome cięcie zakresu w v1: CSS nie ma dziś niezawodnego sposobu na rozpoznanie z poziomu samego CSS, który wariant @position-try faktycznie wygrał, więc dymek nie rysuje "ogonka". Bliskość i cień dymka wystarczają, żeby związek z podświetlonym elementem był czytelny.

3 "Pokaż ponownie" po zapisaniu w localStorage

Tryb deklaratywny obu komponentów zapamiętuje obejrzenie w localStorage (domyślny klucz: ścieżka strony) i nie pokazuje się ponownie. Żeby dać użytkownikowi przycisk "Pokaż wprowadzenie jeszcze raz", wywołaj MoliqueOnboarding.start(slides) / MoliqueTour.start(steps) bezpośrednio z JS - to obejście pomija sprawdzenie localStorage.

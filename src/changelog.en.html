The history of changes, new features and fixes in the molique framework - from the first commit to today's fully modular architecture.

  • v1.7.21
    August 2026

    New Onboarding: Onboarding Slides and Spotlight Tour

    • .onboarding-dialog - full-screen welcome slides (icon/image + title + description) on a native <dialog>. Declaratively via data-onboarding/data-onboarding-slide (shows once per browser, localStorage) or imperatively via MoliqueOnboarding.start(slides).

    • Both APIs return a Promise - they can be chained: MoliqueOnboarding.start(slides).then(() => MoliqueTour.start(steps)). Full docs: Onboarding.

  • v1.7.15
    July 2026

    Fix New "Slate Violet" palette - success/danger/warning/info now pass 4.5:1 with no exceptions

    • The previous --success/--danger/ --warning/--info only worked as a background under dark text - as a standalone text color on a light background they gave a mere 2.3-3.8:1 (below the WCAG 4.5:1 threshold), hence the separate, second set of --success-text etc. The new colors are dark/saturated enough to pass 4.5:1 both ways at once - as text on a light background and as a background under white text - so the second set became redundant. --success-text and the rest stay in the code (dozens of places use them), but are now an alias to the base (--success-text: var(--success)) - zero changes outside _root.scss.
    • New token --semantic-fg: the old success/danger/warning/info were light/pastel in BOTH themes, so buttons/badges always used a hardcoded dark text color. The new ones are dark in light mode, but still light/neon in dark mode - the opposite rule depending on the theme. --semantic-fg switches along with the theme (_buttons.scss, _badges.scss, .bg-success etc. in _colors.scss).
    • Dark-mode --danger isn't 1:1 from the original palette proposal - the version with dark text gave 4.30:1 (AA-large only, not full AA). Picked a slightly lighter shade from the same family - 4.84:1.
    • --primary stays in the same indigo/violet family as before (a minor hue tweak), --secondary shifts to a neutral zinc gray with no blue tint.
  • v1.7.14
    July 2026

    Fix .stat-tile: icon landed above the text instead of beside it

    • The cause wasn't in .stat-tile itself, but in the cascade layers: _stat-tile.scss wrapped its own content in @layer components { ... }, even though molique-style.scss already wraps the entire component import in that same named layer - the extra wrapping inside created a nested sub-layer with lower priority than unwrapped rules in the same scope (including .card). The result: .card's flex-direction: column beat .stat-tile's flex-direction: row, regardless of order in the file.
    • Fixed by removing the unnecessary wrapper - matching most files in components/ (including .card, .tabs), which don't self-wrap. The icon now sits on the left with the text left-aligned beside it, exactly as documented.
  • v1.7.13
    July 2026

    Fix Silent .admin-layout overflow on mobile

    • A bare 1fr in grid-template-columns (mobile, below 768px) is short for minmax(auto, 1fr) - the track's minimum is computed from its descendants' min-content, NOT from zero, even when .admin-main already has min-width: 0 + overflow-x: hidden (a different mechanism from protecting the grid track itself from overflowing). If any descendant - at any depth - has a large intrinsic size, the track grows past the screen width. Because html/body deliberately use overflow-x: clip (not scroll - to avoid breaking position: sticky), the result isn't a visible scrollbar, just content silently clipped past the edge of the screen. Fixed with an explicit minmax(0, 1fr).
    • The same mechanism is now guarded in .tabs-pill too: the tab columns' grid-template-columns is now repeat(var(--tab-count), minmax(0, 1fr)), and labels truncate with an ellipsis instead of wrapping to two lines or overflowing the column when space runs out.

  • v1.7.0
    July 2026

    Fixes Keyboard-accessible tabs

    • .tab-input had display: none - that doesn't just hide the element visually, it removes it from the tab order and the accessibility tree. Tabs couldn't be switched with the keyboard or read by a screen reader, even though the framework declares WCAG 2.2 AAA compliance.
    • Hiding switched to the clip technique - the same one .sr-only is built on. The element becomes invisible but stays focusable: the radio group regains native arrow-key support, and the focus ring lands on the visible .tab-label.
    • Nothing in the markup changes - the same .tabs / .tab-input / .tab-label structure, just fixed behavior underneath.

    New Chart navigation (.chart-nav)

    • A segmented range switcher built on hidden radio inputs - no JavaScript. The component was documented and used in example markup on three pages since the first release, but the CSS rule was never written; now it works.
    • Radios hidden with the clip technique, not display: none - same principle as the tabs fix above, so the group is keyboard-accessible right away.

    New Fewer classes to write: implications in the grid and buttons

    • .grid-md-cols-* is a single-column grid by default below its breakpoint, so class="grid-md-cols-12" is enough. Previously you had to add grid-cols-1, and forgetting it caused a sneaky symptom: the layout looked fine, but gap stopped working on phones - the element wasn't a grid at all at that point.
    • A button color class now implies .btn - class="btn-primary" instead of class="btn btn-primary". This applies to colors and their outline variants. Size and base-look modifiers don't carry it (they're add-ons, not buttons), and .btn-action deliberately doesn't inherit it, since it intentionally breaks the 44px rule.
    • Nothing stops working. The existing class="btn btn-primary" and class="grid-cols-1 grid-md-cols-12" notation is still valid - the new rules only add a default behavior. Cost: +740 B in the buttons module, +62 B in the grid.

    Fixes The 404 page was unstyled

    • 404.html loaded css/flex-ui.css - a file left over from the framework's old name, gone for months. It also used two classes outside molique (.page-404-wrapper, .max-w-600) and a dead js/script.js. Result: a completely unstyled page.
    • Rewritten using only molique classes, without a single line of custom CSS. It serves both as this site's own 404 page and as a template to copy - a comment at the top of the file lists what to swap, plus config for Apache and nginx.

    Change Removed .hover-text-primary and .hover-bg-light

    • They broke the naming scheme. In molique, hover colors are named WHAT-hover-COLOR: text-hover-primary, bg-hover-danger, border-hover-success. These two classes had their parts reversed and were the only ones like that in the whole framework.
    • They were duplicates. The counterparts .text-hover-primary and .bg-hover-light already exist in the palette, and additionally have a transition that the removed versions lacked - so the migration is a minor improvement, not just tidying up.
    • What to do: replace hover-text-primary with text-hover-primary. The class .hover-bg-light wasn't used anywhere in the project. The rest of the hover-* classes (.hover-scale, .hover-shadow, .hover-border-draw, and the rest) don't change - they describe an effect, not a color.

    New CSS variables reference (docs-variables.html)

    • All 148 variables in tables - 86 theme variables (with light and dark mode values), 56 component variables, and 6 markup-driven inputs. For each: what it controls and which SCSS modules use it.
    • The tables are generated by tools/gen-variables-doc.js straight from _root.scss - the values can't drift from the code. The generator fails the build if a SCSS variable appears without a description, or a description is left after a variable was removed.
    • A gotchas section: why --dark turns light in dark mode, why --x-rgb only works inside rgba(), why variables: true in PurgeCSS wipes out the theme, and why you can't use --light-rgb in the sidebar.

    Fixes .bg-glass without a gradient, and a broken sidebar

    • .bg-glass wasn't rendering its tint layer. The background referenced rgba(var(--bg-surface-rgb), …), and that variable was never declared anywhere - a var() with no fallback invalidates the whole declaration, so glassmorphism was running on backdrop-filter alone. The variable was added to both themes.
    • The docs sidebar extracted into a partial. It was duplicated across 19 files and had already drifted: six pages didn't link to the Class Reference or the Roadmap, and docs-tables.html was missing from eighteen menus. Now there's a single partials/docs-sidebar.html, and the active item is set from the URL by a new module, js/modules/molique-admin-nav-active.js.
    • Verified: after the swap, the content of all 22 documentation pages outside the sidebar is byte-for-byte identical, and while fixing .bg-glass, seven of the eight CSS bundles compiled with zero change whatsoever.

    New Splitting SCSS into independent modules (start)

    • _navigation.scss (968 lines) split into 8 standalone files: _navbar, _mega-menu, _dropdown, _breadcrumbs, _pagination, _topbar, _scroll-to-top, _reading-progress. Each can be skipped in a bundle without compile errors - the first step toward the package builder and the molique-nano variant from the roadmap.
    • Verified that nothing was lost: comparison of the compiled CSS before and after the split, at the selector→declaration pair level - 1771 pairs, zero lost, zero added, zero changed. The other bundles (admin, shop, blog…) are bit-for-bit identical.
    • Removed a modularity leak: a single .is-active rule tied together the navbar, dropdown, and mega menu - so a bundle without the mega menu still contained an orphaned .mega-menu-link. Each component now has its own rule.
    • New generator tools/gen-scss-context.js rebuilds _AI_CONTEXT_scss.md from source - this file is a full SCSS dump, so it drifted from reality after every split.

    Change All JS files prefixed with molique-

    • Modules renamed: js/modules/carousel.js → js/modules/molique-carousel.js (and similarly the other 16). The core molique-script.js had the prefix from day one. This lets scripts that sync the framework into a project overwrite only molique's own files, without touching user code.
    • No changes needed in your code if you use the autoloader - the paths live in molique-script.js and were updated. Change something only if you're loading a module manually via <script src>.

    Fixes A dead script and asset discoverability

    • llms.txt and the safelist are now served from the site. Previously the build only copied asset directories, so /llms.txt returned a 404 - and that's the exact address AI agents fetch it from.     Fixes The Background Sync carousel wasn't changing background

    Fixes File Upload: choosing a file gave no confirmation at all

    • .file-upload is an invisible input[type="file"] stretched over the whole card - clicking and native drag-and-drop worked, but there wasn't a single line of JS anywhere in the repo reacting to a selection. Result: after dropping a photo, nothing happened (not even the browser's "open in a new tab" fired - the input silently captured the file).
    • Added molique-file-upload.js: a change listener overwrites (or appends, if it's missing from the markup) .file-upload-name with the selected file's name.

    New Switch as a .grid-expand trigger

    • A third, zero-JS trigger for smooth expanding: .form-switch:has(.form-switch-input:checked) + .grid-expand. A common form pattern ("Send notifications?" → an email field) without a single line of JavaScript.
    • The switch must be a sibling of .grid-expand, not wrap it in the same <label> - otherwise clicking the revealed content also toggles the switch.

    Fixes Sidebar and theme "jumped" on page reload

    • molique-theme and molique-sidebar-state from localStorage were only read on DOMContentLoaded in molique-script.js - i.e. AFTER the browser's first paint. A returning user with a collapsed sidebar (.sidebar-md/ .sidebar-sm) or dark theme would therefore see the default state (full sidebar, light theme) for a split second before it switched.
    • Fix: a small, synchronous inline <script> right at the top of <head>, setting data-theme and the sidebar-md/sidebar-sm class directly on <html> before the first paint, backed by mirrored CSS rules (:root.sidebar-md/ :root.sidebar-sm) in _admin-layout.scss.
    • The existing logic in molique-script.js (switch click, writing to localStorage) was left unchanged - this fix is purely additive. Verified with molique-script.js completely blocked: the page still renders correctly right away.

    Fixes <hr> disappeared in cards - looked like a dot

    • molique never styled <hr> - the element relied entirely on the browser's default style, which among other things centers it via margin-inline: auto. As a direct child of any flex container (most often .card-body, which has been flex-direction: column from the start), those cross-axis auto-margins take priority over align-items: stretch and "eat" all the free space - the line shrank to nearly zero width, showing up as a single dot in the middle of the card.
    • Fixed by adding a base style in _base.scss: width: 100%, margin-inline: 0, border-top: 1px solid var(--border-color). Zero auto-margins, so the problem disappears in every context - not just in cards.
    • The same bug had already been patched once, locally, in .modal-divider - this fix generalizes it to every <hr> in the project, without touching any markup.

    Fixes .form-floating doubled its spacing in a card

    • .form-floating has its own margin-bottom (needed when several fields sit directly in a plain block without a flex wrapper). But .card-body has a gap by default - as its direct child, a field got the spacing twice (gap + its own margin), so the distance to the next field/button was double what it was between other elements in the same card.
    • Fixed with the rule .card-body > .form-floating { margin-bottom: 0; } - outside .card-body, the margin behaves exactly as before.

    New Full-bleed on mobile (.breakout-mobile)

    • A new utility class: pulls an element out of .container's padding on mobile (below 768px), all the way to the screen edge - a typical case is a carousel, an image gallery, or a hero photo inside an article's body that should touch the phone's edges while the rest of the content keeps a normal margin. No effect on desktop.
    • The "viewport centering" technique (width: 100vw + margin-left: 50% + translateX(-50%)) works regardless of the parent's actual padding value - you don't need to know or calculate it. The global guard overflow-x: clip on html (present in molique from the start) prevents the horizontal scroll that 100vw usually triggers when a scrollbar is visible.
    • Requires a direct parent centered in the viewport (like .container) - it works correctly as its direct child, but nested deeper (e.g. inside .card-body) it's calculated against the card's width, not the viewport's, and ends up shifted/clipped. Documented as gotcha #5 on docs-layout.html.

    Architecture Smart JS Autoloader

    • DOM-based Lazy Loading: the monolithic JS file was split into a dozen or so micro-modules (in the js/modules/ folder). The main script scans the page and asynchronously pulls in only the scripts whose components are physically present in the HTML.
    • Local variables: implemented dynamic computation of negative margins for grouped buttons and forms, based on the --btn-border-width variable.

    New Data Viz & Advanced UI

    • Charts (Data Viz): added the _charts.scss module with charts built on Progressive Enhancement (Sparklines, a Radial Bar with CSS Houdini, Heatmaps, an SVG Area Chart, and a Donut Chart).
    • Advanced Inputs: implemented dedicated, visually consistent styles for type="range" (with a filled track), type="color", and type="date".
    • Grouped Elements: added support for .btn-group and .input-group with perfectly overlapping borders.
    • Interactive Icons: added the .status-icon-toggle component (a Plus → Checkmark animation), which can also function as a fully native form checkbox.

    Fixes Bugfixes & UX

    • Grid Blowout: resolved a grid-breaking issue on mobile devices by globally forcing min-width: 0 on grid children.
    • Lightbox Pointer Events: replaced touch events with universal pointerdown/up, allowing photos to be "swiped" using a mouse on desktop as well.
    • Mega Menu: added an "invisible bridge" (pseudo-element) preventing the menu from closing while moving the cursor down away from a link.
    • Mobile Bottom Nav: rebuilt the admin panel's mobile sidebar into a modern, horizontal navigation bar pinned to the bottom of the screen.

    Documentation A Complete Handbook

    • Expanded the documentation to 14 topical subpages.
    • Added instructional blocks (Pro Tips, Requirements, Options) to every component, explaining the architecture and implementation best practices.

  • v1.0.0
    May 2026

    Revolution The molique 2026 Architecture

    • Zero JS for UI: complete removal of JavaScript from Accordions, Tabs, Dropdowns, and Modals. A move to native <details>, <dialog> tags, and the powerful CSS :has() selector.
    • Smart Grid (RAM): replaced the old Flexbox (.row, .col-*) with native CSS Grid. The new .grid-auto class arranges elements automatically without Media Queries.
    • Fluid Typography: implemented clamp() and a Major Third scale. Fonts scale smoothly between mobile and desktop.

    New Accessibility and Performance

    • B2B Target Size: enforced a minimum height of 44px for all interactive elements (WCAG 2.2 AAA compliance).
    • Native Validation: forms now use the :user-invalid pseudo-class, showing errors only after user interaction (no JS).
    • GPU Acceleration: rebuilt the Parallax and animated Blob effects. Moved calculations to the graphics card (60 FPS on mobile).
  • v0.3.0

    Revolution A New Architecture

    • Cascade Layers: rebuilt the framework's main file on a native layer system (@layer). Eliminated specificity wars.

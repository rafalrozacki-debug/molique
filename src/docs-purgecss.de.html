PurgeCSS & Safelist

Wie Sie ungenutztes CSS sicher aus molique entfernen. Eine Schritt-für-Schritt-Anleitung — von der Installation bis zur Prüfung, dass nichts kaputtgegangen ist.

0. Fangen Sie hier an: Vielleicht brauchen Sie das gar nicht

PurgeCSS entfernt CSS-Regeln, die es in Ihren Dateien nicht gefunden hat. Es ist wirksam, birgt aber ein Risiko. Bevor Sie es aktivieren, prüfen Sie einen einfacheren Weg — molique ist in separate Dateien aufgeteilt, und es genügt, die nicht zu laden, die Sie nicht nutzen. Das ist eine Reduktion ohne jedes Risiko.

Datei Größe Wann Sie sie brauchen
molique-style.css ~278 KB Immer Der Framework-Kern.
molique-style-admin.css ~50 KB Nur beim Bau eines Admin-Panels.
molique-style-shop.css ~10 KB Nur für einen Shop (Produktkarten, Warenkorb).
molique-style-blog.css ~7 KB Nur für Blog und Artikel.
molique-style-docs.css ~8 KB Nur für Dokumentationsseiten.
Eine einfache Regel

Entfernen Sie zuerst die Module, die Sie nicht nutzen. Erst wenn das nicht ausreicht, greifen Sie zu PurgeCSS. Die Reihenfolge zählt: Das eine ist kostenlos, das andere kostet Aufmerksamkeit.

1. Warum molique eine Safelist braucht

PurgeCSS liest Ihre Dateien und behält nur die Klassen, die es darin gefunden hat. Das Problem: ein Teil der molique-Klassen kommt in keiner Datei vor — JavaScript fügt sie erst im Browser hinzu (z. B. beim Klick auf ein Akkordeon oder wenn eine Benachrichtigung erscheint). PurgeCSS sieht sie nicht und entfernt sie also — und die Komponente funktioniert nicht mehr.

Eine Safelist ist eine „Das nicht anfassen"-Liste. molique liefert sie fertig mit, Sie müssen sie nicht selbst schreiben.

Was ohne Safelist kaputtgeht Symptom
.is-active und andere Zustände Der aktive Tab, Schritt oder Menüpunkt hebt sich nicht hervor.
toast-* Benachrichtigungen erscheinen ohne Stil (weißes Rechteck).
lightbox-* Das Vergrößern von Fotos sieht aus wie nacktes HTML.
@keyframes toastProgressAnim Die Countdown-Leiste in einer Benachrichtigung steht still.
Was es kostet (gemessen)
  • Ohne PurgeCSS: 278 KB — alles funktioniert.
  • PurgeCSS + Safelist: 68 KB (−75%) — alles funktioniert weiterhin.
  • PurgeCSS ohne Safelist: 53 KB — kleiner, aber die vier oben genannten Dinge sind kaputt.

2. Schritt-für-Schritt-Anleitung

Schritt 1 PurgeCSS installieren

Im Terminal, im Verzeichnis Ihres Projekts: 

npm install --save-dev purgecss

Schritt 2 Die Safelist-Datei finden

Im molique-Paket, neben css/ und js/, liegt die Datei purgecss.safelist.cjs. Kopieren Sie sie in das Root-Verzeichnis Ihres Projekts — dorthin, wo Ihre package.json liegt. 

ihr-projekt/
├── package.json
├── purgecss.safelist.cjs   ← hier
├── css/
│   └── molique-style.css
└── index.html

Schritt 3 Die Konfigurationsdatei erstellen

Erstellen Sie im Root-Verzeichnis purgecss.config.js und fügen Sie den folgenden Inhalt ein. Das ist eine vollständige, funktionierende Konfiguration — nichts muss ergänzt werden. 

const molique = require('./purgecss.safelist.cjs');

module.exports = {
  // Wo PurgeCSS nach Klassennamen suchen soll.
  content: [
    './**/*.html',
    './js/**/*.js',
  ],

  // Welche CSS-Datei wir kürzen.
  css: ['./css/molique-style.css'],

  // Wo das Ergebnis gespeichert wird.
  output: './css/molique-style.purged.css',

  // Die "Nicht anfassen"-Liste - ohne sie funktionieren Komponenten nicht mehr.
  safelist: molique.runtime,

  // Ungenutzte Animationen entfernen (sicher dank der Safelist).
  keyframes: true,

  // NICHT auf true setzen - auf den CSS-Variablen steht das ganze Theme.
  variables: false,
};

Schritt 4 Ausführen 

npx purgecss --config purgecss.config.js

Es entsteht die Datei css/molique-style.purged.css. Tauschen Sie in Ihrem HTML den Verweis darauf aus: 

<link rel="stylesheet" href="css/molique-style.purged.css">

Schritt 5 Prüfen, dass nichts kaputtgegangen ist

Öffnen Sie die Seite und klicken Sie sich durch alles, was JavaScript verwendet. Diese Liste fängt praktisch jedes Problem ab:

  • Akkordeon und Tabs aufklappen — funktioniert die Animation?
  • Ein Modal und aufklappbare Menüs in der Navbar öffnen.
  • Auf ein Foto in der Galerie klicken (Lightbox).
  • Eine Benachrichtigung auslösen — hat sie Farbe und eine Countdown-Leiste?
  • Zu einer anderen Unterseite wechseln — hebt sich die aktive Menüposition hervor?
  • Zwischen hellem/dunklem Theme wechseln.

3. Fertige Konfigurationen

Wählen Sie Ihre Umgebung. Sie unterscheiden sich hauptsächlich darin, wo PurgeCSS nach Klassennamen sucht (content). 

const molique = require('./purgecss.safelist.cjs');

module.exports = {
  content: ['./**/*.html', './js/**/*.js'],
  css: ['./css/molique-style.css'],
  output: './css/molique-style.purged.css',
  safelist: molique.runtime,
  keyframes: true,
  variables: false,
};

Installieren Sie @fullhuman/postcss-purgecss und fügen Sie es als PostCSS-Plugin hinzu. Purge läuft nur beim Produktions-Build. 

// postcss.config.cjs
const purgecss = require('@fullhuman/postcss-purgecss').default;
const molique = require('./purgecss.safelist.cjs');

module.exports = {
  plugins: [
    ...(process.env.NODE_ENV === 'production'
      ? [
          purgecss({
            content: ['./index.html', './src/**/*.{html,js}'],
            safelist: molique.runtime,
            keyframes: true,
            variables: false,
          }),
        ]
      : []),
  ],
};

Hinweis: In WordPress liegt ein Großteil der Klassen in der Datenbank (Beitragsinhalte, ACF-Felder, Blöcke), nicht in Dateien. PurgeCSS sieht sie nicht. Scannen Sie deshalb Ihre PHP-Templates und lesen Sie unbedingt Abschnitt 4 unten. 

const molique = require('./purgecss.safelist.cjs');

module.exports = {
  content: [
    './wp-content/themes/mein-theme/**/*.php',
    './wp-content/plugins/mein-plugin/**/*.php',
    './wp-content/themes/mein-theme/js/**/*.js',
  ],
  css: ['./wp-content/themes/mein-theme/css/molique-style.css'],
  output: './wp-content/themes/mein-theme/css/molique-style.purged.css',

  // In PHP zusammengesetzte Klassen sind unsichtbar - siehe Abschnitt 4.
  safelist: molique.merge('status', 'grid'),

  keyframes: true,
  variables: false,
};

4. Wenn das Backend Klassennamen zusammensetzt

Das ist die häufigste Ursache für „bei mir ist die Hälfte der Stile verschwunden". Wenn Sie einen Klassennamen aus Fragmenten aufbauen, steht er in der Datei nie vollständig — PurgeCSS sieht nur die Bruchstücke und entfernt die Regel.

So sieht das Problem aus
<span class="badge badge-<?= $status ?>">

In der Datei steht nur badge-. Der Name badge-success kommt nirgends vor, also verschwindet die Regel.

Die Lösung
safelist: molique.merge('status')

Behält die gesamte badge-*-Familie, sodass jeder Wert aus der Datenbank funktioniert.

Aktivieren Sie nur die Gruppen, die Sie tatsächlich nutzen — jede behält mehr CSS:

Gruppe Umfasst Aktivieren, wenn Sie zusammensetzen…
'status' badge-, status-, stock-bar-, overlay-, opacity- Status aus der Datenbank, Deckkraftstufen
'grid' col-, offset-, grid-cols- Spaltenbreiten aus einem CMS-Feld
'colors' bg-, text-, border- im Panel gewählte Farben
'spacing' m-, p-, gap- in einer Schleife erzeugte Abstände 
safelist: molique.runtime                      // Minimum
safelist: molique.merge('status')              // + Status aus der DB
safelist: molique.merge('status', 'grid')      // + Spalten aus dem CMS
safelist: molique.all                          // alles (am sichersten)
Eine bessere Lösung, wenn möglich

Statt den Namen zusammenzusetzen, schreiben Sie die vollständigen Klassen im Code aus und wählen eine davon aus — dann sieht PurgeCSS sie und Sie brauchen keine zusätzliche Gruppe: $map = ['ok' => 'badge-success', 'err' => 'badge-danger'];

5. Was Sie nicht tun sollten

  • Setzen Sie nicht variables: true — das entfernt die CSS-Variablen, auf denen das gesamte Theme steht (Farben, Dark Mode, Rundungen). Die Seite verliert ihr Aussehen.
  • Lassen Sie die Safelist nicht weg in der Annahme, „hier nutzt wohl nichts JS". Akkordeons, Benachrichtigungen und Menü-Hervorhebung tun es.
  • Vergessen Sie js/ nicht in content — wenn Ihr eigenes Skript Klassen hinzufügt, muss PurgeCSS diese Datei sehen.
  • Überschreiben Sie nicht das ursprüngliche CSS mit dem Purge-Ergebnis. Speichern Sie in eine neue Datei, damit Sie zurückkönnen.

6. Etwas ist kaputt — was prüfen

Klappen Sie das Symptom auf, das bei Ihnen auftritt.

Eine Komponente sieht aus wie nacktes HTML (kein Stil)

Höchstwahrscheinlich fehlt die Safelist oder ist nicht eingebunden. Prüfen Sie in der Konfiguration, ob Sie safelist: molique.runtime haben und ob der Pfad zu purgecss.safelist.cjs korrekt ist.

Schnelltest: Suchen Sie im resultierenden CSS nach dem Begriff lightbox-overlay. Fehlt er — hat die Safelist nicht funktioniert.

Farben und Theme sind durcheinandergeraten

Sie haben variables: true. Ändern Sie es auf false und bauen Sie erneut. Das molique-Theme basiert auf CSS-Variablen — ihre Entfernung nimmt die gesamte Palette mit.

Status aus der Datenbank haben keine Farben

Das Backend setzt den Klassennamen zusammen. Fügen Sie die Gruppe hinzu: safelist: molique.merge('status'). Details in Abschnitt 4.

Die aktive Position im Menü hebt sich nicht hervor

Die Zustandsklassen .is-* sind herausgefallen. Sie werden von molique.runtime abgedeckt — prüfen Sie, ob die Safelist eingebunden ist und Sie sie nicht mit einer eigenen Liste überschreiben.

Der Gewinn ist minimal (die Datei ist kaum kleiner geworden)

Wahrscheinlich verwenden Sie molique.all oder zu viele Gruppen. Gehen Sie zurück auf molique.runtime und fügen Sie Gruppen einzeln hinzu, wobei Sie nach jeder prüfen, ob alles noch funktioniert.

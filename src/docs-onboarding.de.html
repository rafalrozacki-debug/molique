Onboarding

Zwei unabhängige, vollständig optionale Komponenten zur Einführung neuer Nutzer - keine setzt die andere voraus. Beide laufen auf einem nativen <dialog> (showModal()), sodass Fokus-Trap, Fokus-Wiederherstellung und Schließen mit Esc ohne eigenen Code funktionieren.

1. Was wählen

Komponente Wann Inhalt definieren
.onboarding-dialog Erster Einstieg ins Panel - ein kurzes "was ist das", bevor der Nutzer die Oberfläche sieht. data-onboarding-* ODER MoliqueOnboarding.start()
.tour-dialog Der Nutzer sieht die Oberfläche bereits - Sie müssen zeigen, wo eine bestimmte Funktion liegt. data-tour auf echten Elementen ODER MoliqueTour.start()

Beide zu einem Ablauf verketten

Beide APIs geben ein Promise zurück, das nach dem Schließen des Dialogs (Überspringen, Escape oder Abschluss des letzten Schritts) aufgelöst wird - so lässt sich die Tour direkt nach den Slides starten: 

MoliqueOnboarding.start(slides).then(() => MoliqueTour.start(steps));

2. Onboarding Slides

Vollbild-Willkommens-Slides: ein Icon oder Bild + Titel + Beschreibung, mit Weiter-/Zurück-/Überspringen-Buttons und Fortschritts-Punkten. Im deklarativen Modus erscheinen sie automatisch einmal pro Browser (localStorage) - der Integrator schreibt keine einzige Zeile JS. 

<!-- Deklarative Variante (kein JS) -->
<div data-onboarding hidden>
  <div data-onboarding-slide
       data-onboarding-icon="ph-hand-waving"
       data-onboarding-title="Willkommen im Panel"
       data-onboarding-desc="Kurze Beschreibung des ersten Schritts."></div>
  <div data-onboarding-slide
       data-onboarding-image="img/onboarding/bestellungen.png"
       data-onboarding-image-alt="Screenshot der Bestellliste"
       data-onboarding-title="Bestellungen"
       data-onboarding-desc="Hier verwalten Sie Bestellungen."></div>
</div>

<!-- JS-Variante (dynamische Inhalte) -->
<script>
  MoliqueOnboarding.start([
    { icon: 'ph-hand-waving', title: 'Willkommen im Panel', description: '…' },
    { image: 'bestellungen.png', imageAlt: '…', title: 'Bestellungen', description: '…' },
  ], {
    onSkip: () => {},
    onComplete: () => {},
  });
</script>
Klasse / Attribut Was es macht
.onboarding-dialog Der native <dialog>, von JS erzeugt - Sie schreiben ihn nie von Hand.
.onboarding-card Die Karte der Folie. Breite über --onboarding-card-width (Standard 440px), gesetzt auf :root - die Karte wird per JS erzeugt, es gibt also kein Markup für ein style="". Die Variable erreicht den Mobile-Zweig bewusst nicht, dort füllt die Karte ohnehin den ganzen Bildschirm.
data-onboarding Umschließt die Slides. Optional data-onboarding-key="name" - eigener localStorage-Schlüssel (Standard: der Seitenpfad).
data-onboarding-slide Ein Slide. Reihenfolge = DOM-Reihenfolge. Attribute: data-onboarding-icon (ein Fragment aus dem Icon-Sprite, z. B. ph-hand-waving) ODER data-onboarding-image + data-onboarding-image-alt (schließen sich gegenseitig aus), data-onboarding-title, data-onboarding-desc.
MoliqueOnboarding.start(slides, options) slides: ein Array von Objekten wie oben. options.onSkip / options.onComplete. Gibt ein Promise zurück.

3. Spotlight Tour

Eine Schrittfolge über echte Oberflächenelemente: der Rest des Bildschirms wird abgedunkelt, das hervorgehobene Element bleibt sichtbar, aber nicht anklickbar - showModal() macht das gesamte Dokument außerhalb des Dialogs wirklich inert (Browser-Spezifikation, kein pointer-events-Trick). Nur die eigenen Weiter-/Zurück-/Überspringen-Buttons der Sprechblase steuern die Navigation.

<script>
  MoliqueTour.start([

  ]);
</script>
Klasse / Attribut Was es macht
.tour-dialog Der native <dialog>, von JS erzeugt.
.tour-spotlight Das "Loch" in der Abdunkelung - Position/Größe werden bei jedem Schritt aus getBoundingClientRect() des Ziels berechnet (die klassische Technik box-shadow: 0 0 0 9999px, keine SVG-Maske).
.tour-tooltip Die Sprechblase mit Titel/Beschreibung, positioniert über natives CSS Anchor Positioning (ein per JS auf dem Ziel gesetzter anchor-name + eine 5-fache @position-try-Fallback-Kette, damit sie nie über den Viewport hinausragt). Breite über --tour-tooltip-width (Standard 320px) - die Begrenzung auf die Bildschirmbreite bleibt unabhängig vom gesetzten Wert bestehen.
data-tour Markiert ein echtes Element als Tour-Schritt. Optional data-tour-group="name" (Standard "default") - mehrere unabhängige Touren auf einer Seite.
data-tour-title / data-tour-desc Der Sprechblasen-Inhalt für diesen Schritt. Schrittreihenfolge = DOM-Reihenfolge (dieselbe Regel wie data-gallery-Gruppen in der Lightbox) - kein separates nummeriertes Index-Attribut.
MoliqueTour.start(steps, options) steps: ein Array aus { target, title, description } (target - ein Selektor ODER ein lebendes Element). options.onStepChange / onSkip / onComplete. Gibt ein Promise zurück.

4. Fallstricke und bewusste Einschränkungen

1 Elemente, die NACH dem Laden zur Seite hinzugefügt werden

Der deklarative Scan ([data-tour] / [data-onboarding]) passiert EINMAL, beim Laden des Moduls - genau wie bei der Lightbox, ohne MutationObserver. Ein später gerenderten Panel (Ladeanzeige, Hydration) benötigt MoliqueTour.start() / MoliqueOnboarding.start() aus JS statt reiner Attribute.

2 Keine Richtungs-Spitze an der Sprechblase

Ein bewusster Umfangsschnitt für v1: CSS hat heute keine zuverlässige Möglichkeit, allein aus CSS heraus zu erkennen, welche @position-try-Variante tatsächlich gewonnen hat - die Sprechblase zeichnet daher keine "Zeiger"-Spitze. Nähe und der eigene Schatten der Sprechblase halten den Bezug zum hervorgehobenen Element trotzdem lesbar.

3 Erneutes Anzeigen nach Speicherung in localStorage

Der deklarative Modus beider Komponenten merkt sich in localStorage (Standard-Schlüssel: der Seitenpfad), dass er gesehen wurde, und zeigt sich danach nicht erneut. Um dem Nutzer einen "Einführung erneut anzeigen"-Button zu geben, rufen Sie MoliqueOnboarding.start(slides) / MoliqueTour.start(steps) direkt aus JS auf - dieser Aufruf umgeht die localStorage-Prüfung.

4 Viele Schritte: Punkte weichen dem Zähler

Nichts begrenzt die Zahl der Folien oder Schritte, und die Punktreihe wuchs mit ihr - eine ausreichend lange Sequenz schob den "Weiter"-Button aus der Karte heraus. Der Fehler war unsichtbar: Der Button blieb im DOM, klickbar und in der Tab-Reihenfolge, und die Karte hat overflow: hidden, also erschien nicht einmal eine Bildlaufleiste. Seit v1.7.30 bricht die Fußzeile um (flex-wrap), die Punkte sind das Einzige, was schrumpfen darf, und die Navigation weicht nie. Oberhalb einer Schwelle (8 Onboarding-Folien, 6 Tour-Schritte) verschwinden die Punkte ganz und der sichtbare Zähler "Schritt N von M" übernimmt - derselbe, der zuvor nur Screenreadern vorbehalten war.

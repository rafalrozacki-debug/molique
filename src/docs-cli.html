CLI molique-jit

Wiersz poleceń, którym obsługujesz silnik molique JIT: budowanie, tryb nasłuchujący na żywo, konfiguracja — plus osobny generator gotowych bloków HTML.

To jest podgląd — pakiet jeszcze nie jest na npm

CLI opisane na tej stronie istnieje, działa i zostało ręcznie zweryfikowane — to nie jest zapowiedź funkcji, której jeszcze nie ma. Jedyne, czego naprawdę brakuje, to pierwsza publikacja pakietu molique-jit w rejestrze npm, więc npx molique-jit nie zadziała jeszcze „z marszu”.

Do tego czasu najszybszy sposób, żeby to zobaczyć w akcji, to zbudować pakiet lokalnie ze źródeł — patrz sekcja Instalacja ze źródeł niżej. Kod źródłowy jest jawny w repozytorium: github.com/rafalrozacki-debug/molique.

1. Instalacja ze źródeł (do czasu publikacji na npm)

Wymaga Node.js. Sklonuj repozytorium i zbuduj pakiet lokalnie: 

git clone https://github.com/rafalrozacki-debug/molique.git
cd molique/tools/jit/package
npm install
npm run build

Od tego momentu node dist/cli.js zachowuje się dokładnie tak, jak w tej dokumentacji opisane jest npx molique-jit — wystarczy podmienić jedno na drugie: 

node dist/cli.js init
node dist/cli.js build --minify
node dist/cli.js make:component

Po publikacji na npm ta sekcja zniknie, a wszystkie przykłady niżej (z npx molique-jit …) zadziałają bez żadnej zmiany składni — CLI już dziś jest napisane pod docelowy sposób użycia.

2. Plik konfiguracyjny molique.config.mjs

Komenda init tworzy ten plik za Ciebie, z komentarzami przy każdym polu. Pełny, ręcznie napisany przykład: 

// molique.config.mjs
export default {
  // Gdzie szukać nazw klas.
  content: ['**/*.html', '**/*.php'],

  // Gdzie zapisać wynikowy CSS.
  output: 'css/molique-jit.css',

  // WYŁĄCZNIE klasy specyficzne dla Twojego projektu (np. składane w PHP).
  // Klas runtime'owych molique (toasty, karuzela, stany .is-*) NIE trzeba
  // tu wpisywać — silnik dołącza je automatycznie.
  safelist: ['badge-success', 'badge-danger'],
};

Jeśli masz kilka niezależnych stron w jednym projekcie (np. główną witrynę i osobny landing kampanii), pole targets zastępuje content/ output powyżej i buduje każdy cel osobno — landing dostaje własny, mały plik CSS, bez reszty: 

export default {
  targets: [
    { content: ['src/**/*.html'], output: 'css/molique-jit.css' },
    { content: ['landing-kampania.html'], output: 'css/landing-kampania.css' },
  ],
};
Pole Domyślnie Opis
content ['**/*.html', '**/*.php'] Gdzie szukać klas (wzorce glob).
output css/molique-jit.css Ścieżka pliku wynikowego.
safelist [] Klasy Twojego projektu, których skan mógłby nie znaleźć (np. sklejane w backendzie).
minify false Obecnie efektywnie bez znaczenia — źródłowe dane są już skompresowane u źródła.
targets — Lista niezależnych buildów; gdy podana, zastępuje content/output.

3. Komendy CLI

Binarka nazywa się molique-jit (nie samo molique), żeby nie kolidować z innymi narzędziami o krótszej nazwie. CLI rozumie polecenia po angielsku, ale też ich polskie i niemieckie odpowiedniki — wygodne w zespołach, które na co dzień mówią jednym z tych języków.

Angielski (kanoniczny) Polski alias Niemiecki alias Co robi
init start start Tworzy plik molique.config.mjs ze wzorcową konfiguracją.
build buduj bauen Jednorazowo kompiluje CSS do pliku(ów) wyjściowego(ych).
watch obserwuj beobachten Nasłuchuje zmian plików i przebudowuje na żywo (~50ms debounce).
--minify / -m --minifikuj --minifizieren Wymusza kompresję wyjścia.
--config / -c --konfiguracja --konfiguration Wskazuje własną ścieżkę pliku konfiguracyjnego.

Wszystkie trzy warianty językowe robią dokładnie to samo:

npx molique-jit init
npx molique-jit build --minify
npx molique-jit watch --config ./custom.config.mjs
npx molique-jit start
npx molique-jit buduj --minifikuj
npx molique-jit obserwuj --konfiguracja ./custom.config.mjs
npx molique-jit start
npx molique-jit bauen --minifizieren
npx molique-jit beobachten --konfiguration ./custom.config.mjs

Kody wyjścia

build kończy się kodem 0 przy sukcesie i 1 przy błędzie (np. gdy plik konfiguracyjny wskazuje nieistniejący folder) — wygodne do spięcia z CI, np. jako krok przed publikacją.

4. Generator komponentów: make:component

Osobna komenda, niezależna od budowania CSS. Uruchamia w terminalu interaktywny kreator (strzałki + Enter), a na końcu wypisuje gotowy, wklejalny blok HTML — zgodny co do znaku z prawdziwymi, działającymi przykładami modali w tej dokumentacji.

Stan dzisiejszy: pierwsza iteracja generatora obsługuje wyłącznie Modal (natywny <dialog>), w trzech wariantach opisanych niżej. Generator tabel B2B i szablonów całych stron (opisane jako pomysł w Roadmapie) nie są jeszcze zaimplementowane — nie polegaj na nich, dopóki nie pojawią się tutaj. To jest też pierwsza komenda z rodziny make:* — kolejne (np. make:table) dołączą do tej samej sekcji, gdy powstaną. 

npx molique-jit make:component

Kreator pyta kolejno o:

Standard

Zwykły modal: tytuł, treść, przycisk otwierający (etykieta + kolor).

Confirm

Dialog potwierdzający: pytanie, opis, etykiety przycisków Anuluj/Potwierdź, kolor akcji (np. danger dla usuwania) i ikona ostrzeżenia.

Context

Boczne menu kontekstowe: tytuł oraz dwie pierwsze pozycje akcji (etykieta + ikona) — kolejne dopisujesz ręcznie, kopiując wygenerowany wzorzec.

Na koniec wybierasz, czy kod ma trafić na ekran konsoli (do skopiowania myszką) czy od razu zapisać się do pliku — narzędzie nigdy nie nadpisuje istniejącego pliku bez wyraźnego potwierdzenia.

Form Basics

Ready-to-copy variants of molique's basic text fields - floating labels, native validation, sizes, a self-expanding textarea, and data masking in a real form.

Floating Labels

The label sits inside the field and smoothly floats upward when clicked or once typing starts. 

<div class="form-floating">
  <!-- The placeholder=" " attribute is required for the CSS magic to work! -->
  <input type="text" class="input" id="name" placeholder=" ">
  <label for="name">Full name</label>
</div>

Native Validation (Zero JS)

Uses the :user-invalid pseudo-class - the error message only appears once the user leaves an incorrectly filled-in field.

Please enter a valid email address. 
<div class="form-floating">
  <input type="email" class="input" id="email" placeholder=" " required>
  <label for="email">Work email</label>

  <!-- Error message (CSS shows it automatically via :user-invalid) -->
  <div class="feedback-invalid">Invalid email address.</div>
</div>

Size Variants (sm / lg)

Every element with the .input class - input, select, and textarea - supports the same size modifiers. 

<input type="text" class="input input-sm" placeholder="Compact">
<input type="text" class="input" placeholder="Default">
<input type="text" class="input input-lg" placeholder="Large">

<select class="input input-sm">...</select>

One-Line Textarea (Auto-Expand)

The field occupies the height of a single line, then expands to several rows once clicked or filled in - no JavaScript required. 

<textarea
  class="input textarea-expandable"
  rows="1"
  placeholder="Click to expand…"
  style="--textarea-rows-expanded: 8;"
></textarea>

Masking in a real form

The data-mask attribute formats a field as it is typed, and sets the things most often forgotten when a form is written by hand: inputmode, autocomplete, pattern and maxlength. Below is a whole payment block as it looks in an admin panel: masks work together with floating labels and native validation, without a line of your own JavaScript.

Payment details

Enter the name on the card.
Check the card number.
The server also receives the value without spaces, in a hidden iban_raw field. 
<form>
  <div class="card">
    <div class="card-header">
      <h3 class="text-5 fw-bold m-0">Payment details</h3>
    </div>
    <div class="card-body">
      <!-- m-0 drops the field's own margin; the grid gap does the spacing -->
      <div class="grid-md-cols-3 gap-3">
        <div class="form-floating m-0 col-md-span-2">
          <input type="text" class="input" id="card" placeholder=" " data-mask="card" required>
          <label for="card">Card number</label>
          <div class="feedback-invalid">Check the card number.</div>
        </div>
        <div class="form-floating m-0">
          <input type="text" class="input" id="exp" placeholder=" " data-mask="card-expiry">
          <label for="exp">Expiry</label>
        </div>
      </div>

      <div class="grid-md-cols-3 gap-3">
        <div class="form-floating m-0">
          <input type="text" class="input" id="zip" placeholder=" " data-mask="postal-de">
          <label for="zip">Postal code</label>
        </div>
        <div class="form-floating m-0 col-md-span-2">
          <input type="text" class="input" id="city" placeholder=" ">
          <label for="city">City</label>
        </div>
      </div>

      <!-- the clean value as well, in a hidden field -->
      <div class="form-floating">
        <input type="text" class="input" id="iban" placeholder=" "
               data-mask="iban" data-mask-unmasked-name="iban_raw">
        <label for="iban">IBAN</label>
      </div>
    </div>
    <div class="card-footer d-flex justify-content-end">
      <button type="submit" class="btn-primary">Save details</button>
    </div>
  </div>
</form>

Two things that are easy to miss

Masks do not work on type="number" or type="email" - those types cannot carry a caret, so the module refuses and warns in the console. Do not add your own maxlength either: the masked value is longer than the bare one, so a single number cannot serve both states, and the module derives the limit itself. Polish projects also get nip-pl, phone-pl, postal-pl and nrb-pl; the full list of presets and pitfalls is on the Inputs & Validation page.

Kontext: Ein schlankes, rigoros optimiertes B2B-CSS-Framework.

1. GOLDENE REGELN (CORE RULES)

  • Natives HTML5/CSS statt JS: Bevorzuge immer native Lösungen (<dialog>, <details>, :user-invalid, scroll-snap, popover). JS ist das letzte Mittel.
  • Keine Spezifitätskriege: CSS basiert auf @layer-Kaskadenebenen. !important ist verboten (außer für Utility-Klassen in @layer utilities).
  • B2B-Barrierefreiheit (A11y): Interaktive Elemente (button, input) müssen min-height: 44px haben (Variable --target-size-min). Ausnahme: .btn-action-Buttons in dichten Tabellen.
  • GPU-Performance: Animationen dürfen ausschließlich transform, scale, translate und opacity ändern. Niemals box-shadow, width, height animieren (Reflow vermeiden).

2. KLASSENWÖRTERBUCH & HTML-STRUKTUREN (CHEAT SHEET)

Layout & Grid

  • Smart Grid (Auto): .grid-auto, .grid-auto-sm, .grid-auto-lg. (Ordnet Spalten automatisch an).
  • Starres Grid: Elternelement .grid-cols-1 bis 12. Kinder .col-span-1 bis 12. Die Varianten .grid-md-cols-* und .grid-lg-cols-* sind unterhalb ihres eigenen Breakpoints STANDARDMÄSSIG einspaltig, daher genügt class="grid-md-cols-12" - das Hinzufügen von grid-cols-1 ändert nichts.
  • GOLDENE GRID-REGEL (RWD): Auf Mobilgeräten (innerhalb von .grid-cols-1) NIEMALS .col-span-*-Klassen verwenden. Elemente nehmen standardmäßig 100 % Breite ein. Verwende AUSSCHLIESSLICH Klassen mit dem Präfix -md- (z. B. .col-md-span-6), um das Desktop-Layout zu definieren! .col-span-12 auf Mobilgeräten sprengt den Bildschirm.
  • Offsets (Grid): .col-start-1 bis 12 ODER klassisch .offset-1 bis 11 (sowie Varianten -md-, -lg-). Erlaubt das Verschieben von Elementen im Grid.
  • Flexbox: .d-flex, .flex-column, .align-items-center, .justify-content-between, .gap-1 bis .gap-5. Einzelnes Kind: .align-self-start/-end/-center/-stretch.
  • Abstände: .m-1 bis .m-5, .p-1 bis .p-5 (sowie Varianten -md-, z. B. .p-md-4). Nach oben ziehen (negativer Rand): .overlap-up-50/-100/-150.
  • Positionierung: .position-relative/-absolute/-fixed/-sticky; Kanten .top-0/.bottom-0/.left-0/.right-0/.inset-0; Zentrierung .top-50+.left-50+.translate-middle(-x/-y). Größen: .w-25/-50/-75/-100/-auto, .mw-100, .min-vh-100.
  • Breakout (Full-Bleed auf Mobilgeräten): .breakout-mobile - zieht ein Element unterhalb von 768px aus dem Innenabstand von .container heraus, bis zum Bildschirmrand (Karussells, Galerien, ein Hero-Bild im Textkörper). Auf dem Desktop ohne Effekt. Die Viewport-Zentrierung (width:100vw + margin-left:50% + translateX(-50%)) wird relativ zum DIREKTEN Elternelement berechnet, das im Fenster zentriert sein muss wie .container - eine tiefere Verschachtelung (z. B. in .card-body) verfälscht das Ergebnis.
  • Bento Grid: .bento-grid > .bento-col-2, .bento-row-2.

Navigation (Navbar)

  • Basis: .navbar > .navbar-container > .navbar-brand + .navbar-menu > .navbar-item.
  • Aktive Position (aktuelle Seite): die Klasse .is-active auf .navbar-item (sowie .dropdown-item / .mega-menu-link) - Primärfarbe + stärkere Schriftstärke. Wird anhand der URL vom Modul js/modules/molique-navbar-active.js vergeben (automatisch geladen, sobald .navbar-menu vorhanden ist): hebt den Link der aktuellen Seite UND den Auslöser des Dropdowns, in dem er liegt, hervor. Trage die Aktivität NICHT ins Markup ein - die Navbar wird oft seitenübergreifend geteilt, das Skript erledigt es anhand der Adresse.
  • Varianten: .navbar-transparent, .navbar-sticky (fügt .is-scrolled hinzu).
  • Überlagernde Varianten (.navbar-transparent, .navbar-pill): position: absolute - die Navbar liegt ÜBER dem Inhalt, sodass ein Hero-Foto direkt vom oberen Seitenrand beginnt. Nach dem Scrollen fügt JS .is-scrolled hinzu → position: fixed + Theme-Hintergrund. NICHT mit .navbar-sticky kombinieren (sticky kehrt in den Dokumentfluss zurück und gewinnt in der Kaskade - die Überlagerung funktioniert dann nicht mehr). Schiebe den Hero-Inhalt um var(--navbar-h) nach unten.
  • Pille: .navbar-pill - die Navbar als vom Rand abgesetzte Pille mit eigenem Hintergrund; nach dem Scrollen entfaltet sie sich zu einer Leiste am Rand. Der Hintergrund ist IMMER dunkel (sie liegt über einem Foto), überschreibbar via style="--navbar-pill-bg: #123". Beide Zustände haben GETRENNTE Variablen (ein Inline-Stil schlägt eine Klassenregel, eine gemeinsame Variable würde also den anderen Zustand blockieren): --navbar-pill-bg/--navbar-pill-color über dem Hero, --navbar-pill-bg-scrolled/--navbar-pill-color-scrolled nach dem Scrollen, --navbar-pill-padding-x (32px)/--navbar-pill-padding-x-scrolled (16px). Links bleiben weiß bis zum Scrollen. Auf Mobilgeräten übernimmt das Offcanvas-Panel --navbar-pill-bg (sonst würden weiße Links auf dem hellen --bg-surface landen); bei .navbar-transparent, das nichts hat, um das Panel einzufärben, kehren die Links dort zu --text-main zurück.
  • Offcanvas (Mobil): Basiert auf dem Checkbox Hack (.navbar-offcanvas-toggle:checked).
  • Mega Menu: <details class="mega-menu" name="gruppe"> > <summary class="navbar-item mega-menu-trigger"> + .mega-menu-content (darin .mega-menu-group mit .mega-menu-col-title und .mega-menu-link, optional .mega-menu-featured). Öffnet sich per KLICK, nicht bei Hover - natives <details>, funktioniert mit der Tastatur und ohne JS. Auf Mobilgeräten degradiert es zu einem Akkordeon im Offcanvas. name schließt mehrere Mega-Menüs gegenseitig aus.
  • Dropdown (Navbar): <details class="dropdown"> > <summary class="dropdown-toggle"> + .dropdown-menu.
  • Dropdown Popover (außerhalb der Navbar - Top Layer): ein beliebiger <button popovertarget="ID"> + .dropdown-menu mit einem popover-Attribut und eindeutiger id - das Menü wird NICHT von overflow abgeschnitten (Tabellen, Karten, Modale) und verankert sich automatisch an seinem Button (impliziter Anchor, kein .dropdown-Wrapper nötig). Rechtsbündig zusätzlich mit .dropdown-menu-end.
  • Theme Switch (Hell/Dunkel): <label class="theme-switch"> > <input type="checkbox" id="theme-toggle" class="theme-switch-input"> + .theme-switch-track (mit .theme-switch-thumb und .theme-icon-wrapper > .theme-icon.icon-sun / .theme-icon.icon-moon). id="theme-toggle" ist PFLICHT - molique-script.js sucht es über getElementById; eine andere id oder ein zweiter Schalter auf der Seite = stiller Ausfall, ohne Fehler. Die Wahl wird in localStorage unter molique-theme gespeichert, beim ersten Besuch wird prefers-color-scheme gelesen, das Theme ist das Attribut data-theme auf <html>. Wird auch synchron in <head> gelesen - siehe Admin Sidebar Anti-FOUC weiter unten.
  • Language Switch (Popover): <button class="language-switch-trigger" popovertarget="ID"> (mit .language-switch-flag + Sprachcode) + .dropdown-menu.dropdown-menu-end.language-switch-menu mit einem popover-Attribut und id > .dropdown-item.language-switch-item (mit .language-switch-flag, .language-switch-name, optional .language-switch-check). Flaggen AUSSCHLIESSLICH als einzelne SVG-Dateien aus img/flags/ (<img src="img/flags/pl.svg" width="20" height="15" alt="">) - der Ordner enthält nur die im Projekt tatsächlich angebotenen Sprachen; NIEMALS Emoji-Flaggen (werden unter Windows nicht gerendert) oder ein externes Sprite mit <use> (funktioniert nicht bei file:// und wird gelegentlich von CORS blockiert). Echte Inhaltsübersetzung: die Referenzimplementierung (flache Dateien page.html/page.en.html/page.de.html, Auto-Hreflang, Ausblenden von Sprachen ohne Übersetzung für eine bestimmte Seite) ist in der DOCS-PLAN.md dieses Repos beschrieben und in vite.config.js implementiert (computeI18nLocals).

3. JAVASCRIPT-ARCHITEKTUR

  • Autoloader: Die Hauptdatei molique-script.js durchsucht das DOM und lädt asynchron Mikromodule aus js/modules/ (z. B. carousel.js, lightbox.js) nur dann, wenn die passende Komponente auf der Seite vorhanden ist.
  • Vanilla JS: jQuery ist vollständig verboten.
  • Dateinamen tragen immer das Präfix molique- - gilt für alles, was in ein fremdes Projekt gelangt: der Kern (molique-script.js), JS-Module (js/modules/molique-*.js), CSS-Bundles (css/molique-style*.css) und Konfigurator-Chunks (dist/chunks/molique-*.css). Das erlaubt Sync-Skripten, ausschließlich die eigenen Dateien des Frameworks zu überschreiben. Den Chunk-Namen vergibt tools/gen-chunks.js und schreibt ihn ins Manifest - der Konfigurator liest ihn von dort.
  • NIEMALS Klassennamen dynamisch zusammensetzen ('toast-' + type, `col-span-${n}`) - ein solcher Name existiert nicht als Literal im Quelltext, weder PurgeCSS noch der Safelist-Generator können ihn sehen. Verwende stattdessen eine Literal-Map: const T = { success: 'toast-success', … } + T[type] || T.info.
  • Zustände immer als .is-* (is-active, is-hidden, is-selected) - die Konvention, auf der das Safelist-Muster beruht.

4. PURGE / CSS-GRÖSSE

  • Erst Module, dann Purge: die Wahl der Bundles (Admin, Shop, Blog…) ist eine risikofreie Reduktion; PurgeCSS kommt erst danach.
  • Safelist: das Paket enthält purgecss.safelist.cjs. safelist: molique.runtime = das Minimum (von JS hinzugefügte Klassen). molique.merge('status','grid'), wenn das Backend Klassennamen zusammensetzt (z. B. badge-<?= $status ?>). Ohne die Safelist fliegen unter anderem .is-*, toast-*, lightbox-*, @keyframes toastProgressAnim raus.
  • Niemals variables: true - auf den CSS-Variablen steht das gesamte Theme. Effekt auf einer realen Seite: 277 KB → 68 KB (−75 %).

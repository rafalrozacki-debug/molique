Na npm

molique JIT

Silnik, który generuje tylko ten CSS, którego realnie użyłeś - bez PurgeCSS, bez safelisty, bez zgadywania. Obsługiwany z wiersza poleceń - patrz CLI molique-jit.

Pakiet molique-jit jest opublikowany na npm 

npm install --save-dev molique-jit
npx molique-jit init
npx molique-jit build

Pełna instalacja, konfiguracja i referencja wszystkich komend - na stronie CLI molique-jit. Strona pakietu: npmjs.com/package/molique-jit.

1. Czym to się różni od PurgeCSS

Na stronie PurgeCSS & safelista opisany jest sposób „od dużego do małego” - bierzesz cały gotowy CSS molique i wycinasz z niego to, czego nie widać w Twoich plikach. Działa, ale wymaga safelisty (bo część klas dodaje dopiero JavaScript) i niesie ze sobą ryzyko: jeśli PurgeCSS czegoś nie zobaczy, a Ty zapomnisz o safeliście, komponent przestaje działać po cichu.

molique-jit idzie w drugą stronę: zaczyna od zera i dokłada wyłącznie te klasy, które faktycznie znalazł jako literalny tekst w Twoich plikach HTML/JS. Nic nie usuwa, więc nie ma czego „zapomnieć” w safeliście - klasy uruchamiane przez JavaScript (toasty, lightbox, stany .is-*) są wbudowane w silnik jako zawsze-dołączane, dokładnie tak samo jak w gotowej safeliście PurgeCSS.

PurgeCSS (dziś, gotowe) molique-jit (podgląd)
Punkt startowy Cały skompilowany molique-style.css Zero - dokłada tylko dopasowane klasy
Wymaga safelisty Tak, ręcznie podpięta (purgecss.safelist.cjs) Nie - klasy runtime'owe są wbudowane w silnik
Tryb na żywo (watch) Trzeba spiąć osobno (np. wtyczka PostCSS) Wbudowany: watch / obserwuj / beobachten
Generator komponentów HTML Brak 8 generatorów make:* (patrz CLI)

Nie musisz wybierać jednego na zawsze

Obie ścieżki rozwiązują ten sam problem (mniejszy plik CSS na produkcji) w inny sposób. molique-jit to prostsza, zero-konfiguracyjna alternatywa dla PurgeCSS w nowych projektach - a strona o PurgeCSS zostaje jako opcja dla wszystkich, którzy wolą podpiąć to pod istniejący pipeline budowania.

2. Jak to działa (w skrócie)

Klasy narzędziowe molique (.pb-md-4, .text-hover-primary itd.) nie są dowolne - to skończony, w pełni znany z góry zbiór, wyliczony raz przy kompilacji frameworka. Dzięki temu silnik JIT nie liczy CSS w locie - zamiast tego pracuje jak słownik:

1

Skanuje

Przegląda Twoje pliki (HTML, JS, PHP - cokolwiek wskażesz w content) i wyłapuje wszystkie tokeny wyglądające jak nazwa klasy.

2

Dopasowuje

Sprawdza każdy token w gotowym słowniku klas molique (odczyt, nie obliczenie). Token spoza słownika to po prostu Twoja własna klasa - nie błąd.

3

Kopiuje

Wypisuje gotowe reguły CSS 1:1 z prawdziwie skompilowanego frameworka, zachowując kolejność warstw @layer.

Efekt: wynikowy plik jest identyczny co do bajta z tym, co dałby pełny molique-style.css dla tych samych klas - silnik niczego nie „dogaduje” ani nie przelicza samodzielnie.

Jak tego użyć?

Silnik obsługujesz komendami init/build/watch z wiersza poleceń - instalacja, plik konfiguracyjny, pełna lista komend (z polskimi i niemieckimi aliasami) i generator gotowych komponentów HTML są opisane na osobnej stronie CLI.

1. Start-Vorlage (Boilerplate)

Kopieren Sie den folgenden HTML-Code, um loszulegen. Er enthält optimiertes Laden von Schriftarten (Variable Fonts) sowie die zentrale Kerndatei.

Wichtige Hinweise:

  • Die Datei molique-script.js muss das Attribut defer haben, damit sie das Rendern der Seite nicht blockiert.
  • <link rel="preload">-Tags verhindern Textsprünge (FOUT/FOIT) beim Laden benutzerdefinierter Schriftarten. 
<!DOCTYPE html>
<html lang="de">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>Mein molique-Projekt</title>

  <!-- Preload Variable Fonts -->
  <link rel="preload" href="fonts/inter-variable.woff2" as="font" type="font/woff2" crossorigin>
  <link rel="preload" href="fonts/poppins-variable.woff2" as="font" type="font/woff2" crossorigin>

  <!-- Haupt-Framework-Styles -->
  <link rel="stylesheet" href="css/molique-style.css?v={{ __version }}">
  <!-- Ihre Overrides (optional) -->
  <link rel="stylesheet" href="css/custom.css">
</head>
<body>

  <h1 class="text-9 fw-black">Willkommen bei molique!</h1>

  <!-- Hauptskript (Autoloader) -->
  <script src="js/molique-script.js" defer></script>
</body>
</html>

2. Dateistruktur und JS-Autoloader

Das Framework wurde für extreme Performance entwickelt. Wir laden keinen Code, den Sie nicht verwenden.

Wie funktioniert DOM-basiertes Lazy Loading?

In der HTML-Datei binden Sie nur eine JavaScript-Datei ein: molique-script.js. Diese Datei scannt die Seitenstruktur. Erkennt sie z. B. die Klasse .carousel, lädt sie automatisch und asynchron die Datei js/modules/molique-carousel.js nach. So lädt jede Unterseite nur die tatsächlich benötigten Bytes.

3. Variablen konfigurieren

Das gesamte Framework basiert auf CSS-Variablen (Custom Properties). Um das Erscheinungsbild an Ihre Marke anzupassen, genügt es, den :root-Block in Ihrer eigenen Datei custom.css zu überschreiben. Kein Neukompilieren von Sass nötig! 

/* Ihre custom.css-Datei */
:root {
  /* Wichtigste Markenfarben */
  --primary: #f97316;
  --primary-hover: #ea580c;
  --primary-rgb: 249, 115, 22;

  /* Eckenradius für alle Komponenten */
  --border-radius: 8px;

  /* B2B-Barrierefreiheit erzwingen (klickbarer Bereich) */
  --target-size-min: 44px;
}

4. Layer-Architektur (@layer)

Das Framework nutzt native CSS-Layer. Das bedeutet, dass Utility-Klassen immer gegenüber Komponenten gewinnen, ohne das toxische !important zu verwenden.

Eine Karte hat standardmäßig den Hintergrund --bg-surface

Aber die Klasse .bg-dark gewinnt dank des Layers @layer utilities! 

<!-- Die Klasse .bg-dark überschreibt den Kartenhintergrund ohne !important -->
<div class="card p-4 bg-dark text-white">
  <h3>Eine Karte hat standardmäßig den Hintergrund --bg-surface</h3>
</div>

5. CSS-Module auswählen

Molique ist modular. Die Hauptstile laden Sie immer, aber fortgeschrittene Komponenten (Shop, Blog, Admin-Panel) haben eigene, unabhängige CSS-Dateien. 

<head>
  <!-- 1. Framework-Kern (erforderlich) -->
  <link rel="stylesheet" href="css/molique-style.css?v={{ __version }}">

  <!-- 2. Optionale Module (nur dort laden, wo Sie sie brauchen) -->
  <link rel="stylesheet" href="css/molique-style-admin.css?v={{ __version }}">
  <link rel="stylesheet" href="css/molique-style-shop.css?v={{ __version }}">
  <link rel="stylesheet" href="css/molique-style-blog.css?v={{ __version }}">
</head>

6. Anforderungen und Kompatibilität

Das Framework nutzt die neuesten W3C-Standards. Wir unterstützen den Internet Explorer nicht.

Verwendete Technologien:

  • CSS Cascade Layers (@layer): Vollständige Unterstützung in Chrome 99+, Safari 15.4+, Firefox 97+.
  • Relationaler Selektor (:has()): Vollständige Unterstützung in Chrome 105+, Safari 15.4+, Firefox 121+.
  • Scroll-Driven Animations: (z. B. Parallax) Laufen nativ in Chrome 115+. In älteren Browsern startet das Framework automatisch einen leichten JavaScript-Fallback.
  • Native Modale (<dialog>): Vollständige Unterstützung in allen modernen Browsern.

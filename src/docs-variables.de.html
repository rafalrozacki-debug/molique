CSS-Variablen

Das gesamte Erscheinungsbild von molique — Farben, Abstände, Typografie, Dark Mode — beruht auf CSS-Variablen. Sie müssen keine einzige Regel überschreiben, um das Theme zu ändern: es genügt, die Werte auszutauschen.

1. Wie es funktioniert

Eine CSS-Variable ist eine benannte Box für einen Wert. Das Framework schreibt niemals eine Farbe fest vor — es greift überall auf eine Variable zurück. Wenn Sie deren Inhalt austauschen, verbreitet sich die Änderung sofort über alle Komponenten, die sie verwenden.

Variablen vererben sich den DOM-Baum hinunter — genau wie die Textfarbe. Deshalb hängt die Reichweite einer Änderung ausschließlich davon ab, auf welchem Element Sie sie deklarieren. Das ist auch der Grund, warum PurgeCSS sie niemals entfernen darf — siehe Fallstrick Nr. 3.

Kategorie Anzahl Deklariert in Wer legt sie fest
Theme-Variablen 89 :root in _root.scss Sie — global, einmal pro Projekt.
Komponenten-Variablen 60 Die Datei der jeweiligen Komponente Das Framework. Einen Teil können Sie im Markup überschreiben.
Markup-Eingaben 6 Nirgends — sie werden nur gelesen Ausschließlich Sie. Ohne sie hat die Komponente keine Daten, aus denen sie schöpfen kann.

2. Einen Wert überschreiben

Drei Reichweiten, von der breitesten zur engsten. Alle funktionieren ohne !important — Sie kämpfen nicht gegen die Spezifität, sondern geben nur einen anderen Wert an.

Reichweite 1 Das gesamte Projekt

Ein eigenes Stylesheet, das nach molique eingebunden wird. Das ist der richtige Weg für das Marken-Theme. 

<link rel="stylesheet" href="css/molique-style.css">
<link rel="stylesheet" href="css/mein-theme.css">   <!-- nach molique -->
/* mein-theme.css */
:root {
  --primary: #7C3AED;
  --primary-hover: #6D28D9;
  --primary-rgb: 124, 58, 237;   /* MUSS zu --primary passen */

  --border-radius: 4px;          /* schärfere Oberfläche */
  --spacing-unit: 6px;           /* engerer Rhythmus im gesamten Framework */
}

Reichweite 2 Ein Abschnitt

Eine Deklaration auf einem Container umfasst alles darin. Nützlich, wenn ein Abschnitt einen anderen Akzent haben soll als der Rest der Seite. 

<section class="container p-5" style="--primary: #059669;">
  <!-- jeder .btn-primary und .text-primary hier ist grün -->
  <button class="btn-primary">Speichern</button>
</section>

Reichweite 3 Ein einzelnes Element

So übergeben Sie Daten aus dem Backend — Fortschritt, Bewertung, Lagerbestand. Der Zahlenwert reist in einer Variable, nicht in einer Klasse, denn Klassen dürfen niemals dynamisch zusammengesetzt werden. 

<div class="star-rating" style="--rating: 4.5;"></div>
<div class="stock-bar stock-bar-warning" style="--stock-filled: 2;"></div>
<div class="chart-radial" style="--val: 75%;"></div>

3. Dark Mode

Das dunkle Theme ist ausschließlich ein anderer Wertesatz — null zusätzliche Regeln und null duplizierte Komponenten. Das Attribut data-theme="dark" auf <html> tauscht 31 der 89 Theme-Variablen aus.

Deshalb müssen Sie beim Hinzufügen einer eigenen Farbvariable diese in beiden Blöcken angeben. Eine nur in :root deklarierte Variable bleibt im Dark Mode gleich und verschwindet höchstwahrscheinlich auf dunklem Hintergrund. 

:root {
  --marken-akzent: #B45309;
}

[data-theme="dark"] {
  --marken-akzent: #FBBF24;   /* heller, damit er auf Dunkel lesbar bleibt */
}
Woher das System-Theme kommt

Beide Blöcke deklarieren auch color-scheme. Das sorgt dafür, dass native Steuerelemente — Scrollbars, der Kalender in input[type="date"], der Hintergrund von <dialog> — dem Theme folgen. Ohne diese Deklaration können Überschriften in einem Modal auf einer dunklen Karte schwarz werden.

4. Vier Fallstricke

Jeder von ihnen hat schon jemanden einen Nachmittag gekostet. Alle laufen auf dasselbe hinaus: Eine Variable sagt nicht, was sie ist — man muss es wissen.

1 --dark bedeutet nicht „dunkel"

Im hellen Theme ist --dark #1E293B (Graphit), aber im Dark Mode kehrt es sich um zu #F8FAFC (Weiß). Das ist nicht „die dunkle Farbe" — es ist die zum Hintergrund kontrastierende Farbe. Ebenso wird --light im Dark Mode dunkel.

Die Folge: verwendet auf einem Element, das auf einem Foto liegt — dessen Hintergrund sich nicht mit dem Theme ändert — ergibt sich weißer Text auf weißem Grund. 

/* FALSCH - auf einem Foto verschwindet der Text im Dark Mode */
.foto-bildunterschrift { color: var(--dark); }

/* RICHTIG - literaler Wert, unabhängig vom Theme */
.foto-bildunterschrift { color: #1E293B; }
2 --x und --x-rgb sind nicht dasselbe

--primary ist eine fertige Farbe. --primary-rgb sind nur die Kanäle (2, 132, 199) — ohne das lässt sich keine Transparenz bauen. Es funktioniert ausschließlich innerhalb von rgba().

Anderswo eingesetzt ist es keine gültige Farbe, also verwirft der Browser die gesamte Deklaration — stillschweigend, ohne Konsolenfehler. 

/* FALSCH - "2, 132, 199" ist keine Farbe, die Deklaration entfällt */
.karte { border-color: var(--primary-rgb); }

/* RICHTIG */
.karte { border-color: var(--primary); }
.karte { background: rgba(var(--primary-rgb), 0.1); }

Wenn Sie --primary in Ihrem Theme ändern, ändern Sie immer auch --primary-rgb. Ein Auseinanderlaufen des Paares ergibt Transparenzen in der alten Farbe.

3 PurgeCSS mit variables: true löscht das Theme

Diese Option entfernt CSS-Variablen, die PurgeCSS in Ihren Dateien nicht gefunden hat. Das Problem: molique's Variablen werden innerhalb der Framework-Regeln selbst verwendet, nicht in Ihrem HTML — das Tool hält sie also für tot und entfernt sie. Ergebnis: eine Seite ohne Farben und ohne Abstände. 

// purgecss.config.js
module.exports = {
  variables: false,   // LASSEN SIE false - auf den Variablen steht das ganze Theme
};

Details und eine fertige Konfiguration: PurgeCSS & Safelist.

4 Die Admin-Sidebar ist immer dunkel

--sidebar-bg hat absichtlich kein Dark-Mode-Gegenstück — die Sidebar sieht in beiden Themes gleich aus. Deshalb müssen ihre hellen Akzente literale Werte sein.

Wird dort --light-rgb verwendet, sieht das im hellen Theme korrekt aus, aber im dunklen kehrt sich diese Variable um — und Text sowie Highlights verschwinden auf dem dunklen Sidebar-Hintergrund. Dafür gibt es die separate --sidebar-highlight-rgb. 

/* FALSCH - der Hover verschwindet im Dark Mode */
.admin-nav-link:hover { background: rgba(var(--light-rgb), 0.1); }

/* RICHTIG - ein vom Theme unabhängiger Akzent */
.admin-nav-link:hover { background: rgba(var(--sidebar-highlight-rgb), 0.1); }

5. Theme-Variablen 89

Deklariert in :root. Die Spalte Dark Mode zeigt den Wert bei aktiviertem dunklem Theme — keine Änderung bedeutet, dass die Variable für beide Themes gilt. Die Spalte Verwendet in zeigt die Sass-Module, die sie nutzen.

Diese Referenztabelle wird automatisch aus dem Sass-Quellcode generiert und ist derzeit nur auf Polnisch verfügbar. Variablennamen (--primary, --spacing-unit…) und Werte benötigen ohnehin keine Übersetzung.

6. Komponenten-Variablen 60

Innerhalb einer bestimmten Komponente deklariert, funktionieren sie also nur in ihrem Bereich. Zwei Arten:

  • markup — dafür vorgesehen, von Ihnen überschrieben zu werden, meist über style="--x: …".
  • intern — das Framework berechnet sie selbst. Aufgeführt, weil sie in den DevTools sichtbar sind und man wissen sollte, dass hier nicht der Ort für eigene Änderungen ist.

7. Markup-Eingaben 6

Variablen, die das Framework niemals selbst deklariert — es liest sie nur. Das ist die Schnittstelle zum Übergeben von Daten aus dem Backend. Steht in der Spalte Wenn nicht gesetzt erforderlich, führt ein fehlender Wert dazu, dass die Komponente nicht korrekt gerendert wird.

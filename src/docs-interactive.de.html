Modale, Tabs & Akkordeons

Komponenten, für die andere Frameworks Hunderte Kilobyte JavaScript aufwenden. Hier übernimmt das der Browser: ein natives <dialog>, <details> und versteckte Radio-Felder. Fertige Blöcke finden Sie in den Beispielen.

1. Wie viel JavaScript jede Komponente braucht

Das ist die wichtigste Tabelle auf dieser Seite. Vier von sieben Komponenten brauchen überhaupt kein Skript — sie funktionieren auch, wenn JS nicht lädt.

Komponente Mechanismus JavaScript
.accordion-item <details> null
.tabs Verstecktes input[type="radio"] null
.tooltip-element Attribut data-tooltip + CSS null
.grid-expand Animiertes grid-template-rows null
.popover-context Popover API + Anchor Positioning nur Umklappen
.modal-dialog Natives <dialog> eine Zeile
.toast Popover API erforderlich

2. Modale

Die Grundlage ist ein natives <dialog>. Der Browser liefert vier Dinge kostenlos, die in JS-Bibliotheken eigenen Code erfordern: einen abgedunkelten Hintergrund (::backdrop), eine Fokus-Falle (Tab entkommt nicht aus dem Modal), Schließen mit der Esc-Taste und die Beförderung in den Top Layer, sodass kein z-index und kein overflow es verdecken kann.

Aktion Wie
Öffnen .showModal() auf dem Element. Das ist die einzige Stelle, an der das Modal JS benötigt — verwenden Sie .showModal(), nicht .show(), siehe Fallstrick Nr. 1.
Schließen per Button Ein Button innerhalb von <form method="dialog">. Der Browser schließt es selbst — null Skript.
Schließen per Klick auf den Hintergrund Wird global von molique-script.js behandelt, für jedes Modal auf der Seite.
Schließen mit der Esc-Taste Nativ. Nichts zu tun. 
<button onclick="document.getElementById('meinModal').showModal()">Öffnen</button>

<dialog id="meinModal" class="modal-dialog">
  <div class="card">
    <div class="card-header">Titel</div>
    <div class="card-body">Inhalt…</div>
    <div class="card-footer">
      <!-- Natives Schliessen, ohne JS -->
      <form method="dialog">
        <button class="btn btn-secondary">Schließen</button>
      </form>
    </div>
  </div>
</dialog>
Klasse Was sie macht
.modal-dialog Ein zentriertes Fenster. Die Basisvariante.
.modal-sm Ein schmaleres Fenster — kurze Meldungen.
.modal-context Ein Seitenpanel auf dem Desktop, auf dem Smartphone ein von unten aufsteigendes Panel (Bottom Sheet). Dasselbe Markup.
.modal-confirm Ein Bestätigungsfenster — zentriertes Icon und zwei Buttons.
.modal-confirm-icon Ein großes Icon über der Frage. Farbe über eine Textklasse vergeben, z. B. .text-danger beim Löschen.
.modal-action-list Eine vertikale Aktionsliste im Seitenpanel.
.modal-action-btn Eine einzelne Aktion in der Liste.
.modal-divider Trennlinie zwischen Aktionsgruppen.
.modal-close-btn Das × in der Ecke. Platzieren Sie es innerhalb eines <form method="dialog">, damit es ohne Skript funktioniert.

3. Akkordeons

Jede Position ist ein <details>. Aufklappen, Tastaturbedienung und Textsuche im eingeklappten Inhalt (Strg+F öffnet den richtigen Abschnitt) sind nativ.

Damit immer nur eine Position gleichzeitig offen ist, geben Sie allen dasselbe Attribut name — der Browser kümmert sich um den Rest, genau wie bei einer Gruppe von Radio-Feldern. 

<div class="accordion">
  <details class="accordion-item" name="faq" open>
    <summary class="accordion-header">Erste Frage</summary>
    <div class="accordion-body">Antwort…</div>
  </details>
  <details class="accordion-item" name="faq">
    <summary class="accordion-header">Zweite Frage</summary>
    <div class="accordion-body">Antwort…</div>
  </details>
</div>
Klasse Auf Was sie macht
.accordion <div> Hülle der Gruppe — Rahmen und Abrundung für das Ganze.
.accordion-item <details> Eine einzelne Position.
.accordion-header <summary> Eine klickbare Leiste mit Pfeil. Bietet Platz für mehrere Elemente nebeneinander (z. B. eine Plakette und Text) — sie bleiben links ausgerichtet.
.accordion-body <div> Der aufklappbare Inhalt.
Etwas anderes aufklappen: .grid-expand

Die Animation von height von null auf „wie viel herauskommt" ist in reinem CSS unmöglich — height: auto lässt sich nicht animieren. Der Trick besteht darin, grid-template-rows von 0fr auf 1fr zu animieren. Nützlich überall dort, wo <details> nicht passt: eine aufklappbare Tabellenzeile, „mehr anzeigen" unter einer Beschreibung.

Zwei Elemente: .grid-expand ist der animierte Container, .grid-expand-inner umhüllt den Inhalt (ohne es gibt es nichts zu komprimieren). Es öffnet sich auf drei Arten — wählen Sie eine, abhängig davon, was das Aufklappen steuert.

Auslöser Wann
.is-open Sie fügen die Klasse selbst hinzu und entfernen sie — z. B. aus eigenem JS.
details[open] .grid-expand liegt innerhalb eines nativen <details> — null JS.
.form-switch + .grid-expand Ein iOS-artiger Switch direkt vor dem Container (Geschwister, nicht verschachtelt) — null JS. 
<div class="grid-expand is-open">
  <div class="grid-expand-inner">Inhalt, der sich aufklappt</div>
</div>

Die dritte Variante — ein Switch (vollständige Beschreibung in der Formulardokumentation), der ein Feld darunter freilegt, ein häufiges Muster in Formularen („Benachrichtigungen senden?" → E-Mail-Adressfeld): 

<label class="form-switch">
  <input type="checkbox" class="form-switch-input">
  <span class="form-switch-label">E-Mail-Benachrichtigungen senden</span>
</label>

<!-- Geschwister des Switch, NICHT im selben <label> ->
     ein Klick im Inhalt darunter wuerde sonst zusaetzlich den Switch umschalten -->
<div class="grid-expand">
  <div class="grid-expand-inner">
    <input type="email" class="input" placeholder="E-Mail-Adresse">
  </div>
</div>

4. Tabs

Tabs sind eine als Reiter getarnte Gruppe von Radio-Feldern. Ein verstecktes input[type="radio"] hält den Zustand, und der sichtbare Tab ist ein <label>, das darauf zeigt. Da nur ein Radio-Feld in einer Gruppe ausgewählt sein kann, erhalten Sie die gegenseitige Ausschließung kostenlos — und dank der Versteckung per clip-Technik statt display: none auch die Bedienung mit den Pfeiltasten. 

<div class="tabs">
  <!-- Zustand: alle Inputs MUESSEN denselben name haben -->
  <input type="radio" name="meine-tabs" id="tab-1" class="tab-input" checked>
  <input type="radio" name="meine-tabs" id="tab-2" class="tab-input">

  <div class="tabs-header">
    <label for="tab-1" class="tab-label">Erster</label>
    <label for="tab-2" class="tab-label">Zweiter</label>
  </div>

  <div class="tabs-content">
    <div class="tab-pane">Inhalt des ersten</div>
    <div class="tab-pane">Inhalt des zweiten</div>
  </div>
</div>
Klasse Was sie macht
.tabs Die Hülle der Komponente.
.tab-input Das versteckte, zustandshaltende Radio-Feld. Gemeinsamer name innerhalb eines Tab-Sets.
.tabs-header Die Leiste mit den Tabs.
.tab-label Der sichtbare Tab. for muss auf die id des passenden Feldes zeigen.
.tabs-content Der Container der Panels.
.tab-pane Ein Inhaltspanel. Die Reihenfolge der Panels muss der Reihenfolge der Radio-Felder entsprechen — siehe Fallstrick Nr. 3.
.tabs-pill Eine Erscheinungsvariante: Tabs als Pillen statt Unterstreichung.
.tabs-pill-indicator Der gleitende Hintergrund der aktiven Pille. Die Breite berechnet sich aus der Variable --tab-count — setzen Sie sie auf die Anzahl der Tabs.

5. Toasts

Die einzige Komponente auf dieser Seite, die JavaScript erfordert — eine Benachrichtigung erscheint naturgemäß als Reaktion auf ein Ereignis, sie kann also nicht im HTML stehen. Sie bauen das Markup nicht selbst; Sie rufen eine Funktion auf. 

MoliqueToast.show({
  message: 'Änderungen gespeichert',
  type: 'success',        // success | danger | warning | info
  position: 'top-right',  // top-left | top-center | top-right
                          // bottom-left | bottom-center | bottom-right
  duration: 4000          // ms
});
Parameter Standard Hinweise
message 'Benachrichtigung' Der Inhalt der Meldung.
type 'info' Ein unbekannter Wert fällt still auf info zurück, statt die Seite zum Absturz zu bringen.
position 'top-right' Der Container für die jeweilige Ecke entsteht bei der ersten Verwendung von selbst.
duration 4000 Zeit in Millisekunden.
Toast-Klassen und PurgeCSS

Die Klassen .toast-success, .toast-top-right und die übrigen kommen nicht in Ihrem HTML vor — das Skript fügt sie hinzu. PurgeCSS hält sie für toten Code und entfernt sie, wodurch Benachrichtigungen ihren Stil verlieren. Deshalb liefert molique eine fertige Safelist; Details in PurgeCSS & Safelist.

Klasse Was sie macht
.toast-container Der Container der Bildschirmecke; wird vom Skript erzeugt.
.toast Eine einzelne Benachrichtigung.
.toast-progress Ein Balken, der bis zum Verschwinden herunterzählt. Die Animation toastProgressAnim muss ebenfalls auf der Safelist stehen.
.toast-success, .toast-danger, .toast-warning, .toast-info Farben gemäß dem Parameter type.
.toast-top-left, .toast-top-center, .toast-top-right, .toast-bottom-left, .toast-bottom-center, .toast-bottom-right Die sechs Positionen gemäß dem Parameter position.
.is-closing Der Zustand beim Verschwinden; wird vom Skript vergeben.

6. Tooltips und Kontextmenüs

Tooltip

Der Inhalt steckt im Attribut data-tooltip, und CSS zeichnet die Sprechblase. Null Skript und null zusätzliche Elemente im Baum. 

<span class="tooltip-element" data-tooltip="Erklärung">Hier hovern</span>

Kontextmenü

Ein kleines Menü, das sich an seinen auslösenden Button heftet. Es basiert auf der Popover API und Anchor Positioning und landet daher im Top Layer — weder ein overflow einer Tabelle noch eine Karte kann es zuschneiden. JavaScript erledigt hier nur eines: Es prüft, ob das Menü über den unteren Fensterrand hinausragen würde, und klappt es dann über den Button (.is-flipped).

Klasse Was sie macht
.tooltip-element Ein Element mit Sprechblase. Erfordert das Attribut data-tooltip.
.popover-context Ein Menü mit dem Attribut popover und eigener id.
.popover-action-btn Ein Menüpunkt.
.is-flipped Das über den Button geklappte Menü bei Platzmangel. Wird von JS vergeben.

7. Fallstricke

1 .show() statt .showModal()

Beide Methoden öffnen ein <dialog>, aber nur .showModal() macht daraus ein Modal. Nach .show() gibt es keinen abgedunkelten Hintergrund, Esc schließt nicht, und der Fokus kann frei auf den Inhalt darunter entweichen — für jemanden, der die Tastatur nutzt, wird das Fenster dann zu einer Falle ohne Ausgang. 

meinDialog.show();       // FALSCH - gewoehnliches Fenster ohne Hintergrund, ohne Esc
meinDialog.showModal();  // RICHTIG
2 Ein Schließen-Button außerhalb von <form method="dialog">

Es ist dieses Formular, das das Modal nativ schließt. Ein daneben platzierter Button bewirkt nichts, bis Sie ihm eine JS-Steuerung hinzufügen. Das gilt auch für das × (.modal-close-btn) in der Ecke.

3 Verschobene Reihenfolge von Tabs und Panels

CSS verbindet ein Radio-Feld mit seinem Panel nach Position, nicht nach Namen — das dritte ausgewählte Feld zeigt das dritte .tab-pane. Ein Panel in einer anderen Reihenfolge als die Inputs zu platzieren oder etwas dazwischen einzufügen, führt dazu, dass die Tabs den falschen Inhalt zeigen.

Eine zweite Variante desselben Fehlers: zwei Tab-Sets auf einer Seite mit demselben name. Ein Klick in einem schaltet beide um.

4 Ungestylte Toasts nach Aktivierung von PurgeCSS

Ein klassisches Symptom: Lokal funktioniert alles, und nach dem Deployment sind die Benachrichtigungen weiße, farblose Rechtecke mit einem stehenden Fortschrittsbalken. Der Grund ist immer derselbe — die toast-*-Klassen werden von JS hinzugefügt, daher sieht sie PurgeCSS nie in den Dateien und entfernt sie. Binden Sie die mitgelieferte Safelist ein.

5 Animation von height statt .grid-expand

height: auto ist nicht animierbar, daher besteht der typische Workaround darin, die Höhe in JS zu messen und in Pixeln einzutragen. Neben dem zusätzlichen Code löst das bei jedem Frame eine Layout-Neuberechnung aus. .grid-expand animiert grid-template-rows und muss die Zielhöhe nicht kennen.

6 .grid-expand innerhalb von <label class="form-switch">

Die Variante „Switch legt Inhalt frei" erfordert, dass .grid-expand ein Geschwister von .form-switch ist, nicht sein Kind. Das gesamte <label> leitet Klicks an sein eigenes <input> weiter — wird .grid-expand hineingesetzt, schaltet ein Klick irgendwo im freigelegten Inhalt (z. B. in einem Formularfeld) zusätzlich den Switch um.

Layout Navigation and element grouping 2

  • Universal .group mechanism - extending the logic already known from .btn-group / .input-group (smoothly joining the edges of adjacent elements) to avatars, icons, and badges.
  • New breadcrumb variants - additional breadcrumb styles, e.g. a shortened path on mobile or icons between levels.

New Forms and fields 5

  • A more expressive selection animation - today a checkbox/radio only has a smooth transition of background and border color (transition); eventually something more noticeable, e.g. a drawn checkmark or a subtle pop on selection - still with no extra classes needed.
  • Character limit and data masking - a remaining-characters counter for text fields and ready-made masks for common formats (phone, payment card, postal code, bank account number).
  • Password strength indicator - a bar or label showing live how strong the entered password is.
  • New field types - a tag input (added as "pills"), an email field with domain suggestions, a person/user picker from a list.
  • One-time code (OTP) input - separate boxes for individual digits with automatic focus-jumping to the next box after a character is entered.

New Buttons 2

  • A counter, icon, or dot overlay on a button - one universal overlay mechanism: a number (e.g. for notifications), an icon (e.g. a plus), or just a dot signaling something new.
  • An expandable phone button - on desktop it shows just a handset icon and expands into the full number on hover; on mobile the number is visible right away, since there's no hover state there.

Component New components 8

  • A half-screen modal - a side or bottom panel variant taking up exactly half the screen's height/width, similar to the windows known from Google Tag Manager.
  • Extended tooltip variants - including one that behaves like a mini-modal, with its own title and action buttons - ideally built on the same styles as .modal-dialog.
  • Automatic card border matching header/footer color - when a card's header or footer has a color assigned (e.g. .bg-primary), the whole card automatically gets a border in that same shade.
  • A real checklist with checkable items - .list-icons-check today only decoratively shows a checkmark icon next to each item; missing is a variant where clicking actually toggles a "done" state (on a checkbox basis, similar to .selection-tile, but in list form).
  • A generic gallery grid tied to the Lightbox - today .product-gallery (a main photo + a row of thumbnails) and the Lightbox work as two separate components; missing is a "thumbnail grid" variant that opens directly in the Lightbox, for use outside a product context (e.g. a project gallery, a portfolio).
  • A generic quote for article content - .testimonial already gives a styled "customer review" with an author and avatar, but that's a component for marketing sections, not for dropping into the middle of blog text. Missing is a lighter <blockquote> variant under _blog.scss.
  • Tables in several sizes - extending the existing .table-sm / .table-lg with additional data-density variants.
  • Size variants for .stat-tile - one fixed size today (proven sufficient in practice), but worth considering e.g. .stat-tile-sm for denser layouts (a row of 8+ tiles on one dashboard).

Feedback Feedback and statuses 2

  • Different toast types - including a variant that doesn't auto-dismiss and requires the user to close it manually.
  • Pulsing text - text pulsing analogously to .status-ping - worth checking whether both animations can be synced in time.

Effect Effects, animations, and typography 6

  • Graphic filters - brightness, contrast, sepia, saturate as ready-made classes (today there's only .filter-grayscale and .filter-blur); also useful as a "pre-hover" state (e.g. a black-and-white photo that gains color on hover).
  • A gradient overlay for text on an image - a ready-made class with a linear-gradient ensuring text readability over a photo background without manually tuning transparency.
  • An extended color scale - more shades and variants in the system color palette.
  • Outlined text - a typographic variant with just the letter outline, no fill.
  • Wiring .file-upload-animated into the shared .hover-border-* library - the library (.hover-border-draw/-trace/-draw-2/-trace-2) already exists, but .file-upload-animated still has its own, separate "marching ants" border animation that doesn't use this mechanism.
  • To investigate Can pure CSS smoothly change font color at the point where the background underneath changes (e.g. text on the boundary between two sections of different colors)?

Data Viz Charts and data 2

  • A gauge/speedometer chart - a needle on a curved scale, e.g. for presenting a single aggregate score or result.
  • Additional stepper variants - extra visual variants alongside the existing .stepper and .stepper-numbered.

Shop Online store 2

  • Hovering the "Add to cart" button enlarges the product photo - today the enlargement (.product-image-wrapper:hover) triggers on hovering the photo itself; the idea is an extra reinforcement of the reaction specifically on hovering the action button, not just the thumbnail.
  • An add-to-cart animation - a short animation of the product "flying" toward the cart icon after clicking.

Admin Admin panel 1

  • A bar above .admin-nav (quick actions, search, notifications) - the framework already has .topbar (marketing navbar context) and .dashboard-header (a bar inside the panel's content), but neither is documented/adapted as a bar directly above the admin sidebar.

DX Documentation and tooling 2

  • Icons: an overview of approaches in the docs - a dedicated section comparing CSS-only solutions, ones requiring JS, and fallbacks, with a clear recommendation on when to use which.
  • A VS Code extension - hints and autocompletion for molique classes right inside the editor.

Native Native elements without classes 5

Places where the bare HTML tag - with no class at all - would look better just from using molique, the same way a plain <hr> or inline <code> already do today.

  • <dialog> and [popover] with no class - today the full look (centering, shadow, animation) only comes with .lightbox-overlay, .modal-dialog, or .dropdown-menu; a bare element renders with the browser's raw default style.
  • <progress> and <meter> - reskinning the native elements (color from --primary, rounded corners) alongside the existing div-based .progress/.stock-bar.
  • <fieldset>/<legend> - resetting the browser's clunky default border into something consistent with --border-color, rounded.
  • <blockquote> (no variant) - a decent look right away instead of the browser's raw indent.
  • <dl>/<dt>/<dd> - definition lists for specs and metadata, mediocre by default today.

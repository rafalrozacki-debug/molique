PurgeCSS & safelista

Jak bezpiecznie wyciąć z molique CSS, którego nie używasz. Instrukcja krok po kroku — od instalacji po sprawdzenie, czy nic się nie zepsuło.

0. Zacznij tutaj: może wcale tego nie potrzebujesz

PurgeCSS wycina reguły CSS, których nie znalazł w Twoich plikach. Jest skuteczny, ale wprowadza ryzyko. Zanim go włączysz, sprawdź prostszy sposób — molique jest podzielony na osobne pliki i wystarczy nie ładować tych, których nie używasz. To redukcja bez żadnego ryzyka.

Plik Rozmiar Kiedy jest potrzebny
molique-style.css ~278 KB Zawsze Rdzeń frameworka.
molique-style-admin.css ~50 KB Tylko gdy budujesz panel administracyjny.
molique-style-shop.css ~10 KB Tylko sklep (karty produktów, koszyk).
molique-style-blog.css ~7 KB Tylko blog i artykuły.
molique-style-docs.css ~8 KB Tylko strony dokumentacji.
Prosta zasada

Najpierw usuń moduły, których nie używasz. Dopiero jeśli to nie wystarczy — sięgnij po PurgeCSS. Kolejność ma znaczenie: pierwsze jest darmowe, drugie kosztuje uwagę.

1. Dlaczego molique wymaga safelisty

PurgeCSS czyta Twoje pliki i zostawia tylko te klasy, które w nich znalazł. Problem: część klas molique nie występuje w żadnym pliku — dodaje je JavaScript dopiero w przeglądarce (np. gdy klikniesz akordeon albo pojawi się powiadomienie). PurgeCSS ich nie widzi, więc je usuwa — i komponent przestaje działać.

Safelista to lista „tego nie ruszaj". molique dostarcza ją gotową, więc nie musisz jej pisać samodzielnie.

Co się psuje bez safelisty Objaw
.is-active i inne stany Aktywna zakładka, krok czy pozycja menu nie podświetla się.
toast-* Powiadomienia pojawiają się bez stylu (biały prostokąt).
lightbox-* Powiększanie zdjęć wygląda jak goły HTML.
@keyframes toastProgressAnim Pasek odliczania w powiadomieniu stoi w miejscu.
Ile to kosztuje (zmierzone)
  • Bez PurgeCSS: 278 KB — wszystko działa.
  • PurgeCSS + safelista: 68 KB (−75%) — wszystko nadal działa.
  • PurgeCSS bez safelisty: 53 KB — mniej, ale cztery rzeczy powyżej są zepsute.

2. Instrukcja krok po kroku

Krok 1 Zainstaluj PurgeCSS

W terminalu, w katalogu swojego projektu: 

npm install --save-dev purgecss

Krok 2 Znajdź plik safelisty

W paczce molique, obok css/ i js/, jest plik purgecss.safelist.cjs. Skopiuj go do katalogu głównego swojego projektu — tam, gdzie masz package.json. 

twoj-projekt/
├── package.json
├── purgecss.safelist.cjs   ← tutaj
├── css/
│   └── molique-style.css
└── index.html

Krok 3 Utwórz plik konfiguracyjny

W katalogu głównym utwórz purgecss.config.js i wklej poniższą zawartość. To jest kompletna, działająca konfiguracja — nie musisz nic dopisywać. 

const molique = require('./purgecss.safelist.cjs');

module.exports = {
  // Gdzie PurgeCSS ma szukać nazw klas.
  content: [
    './**/*.html',
    './js/**/*.js',
  ],

  // Który plik CSS przycinamy.
  css: ['./css/molique-style.css'],

  // Gdzie zapisać wynik.
  output: './css/molique-style.purged.css',

  // Lista "tego nie ruszaj" — bez niej komponenty przestaną działać.
  safelist: molique.runtime,

  // Usuwaj nieużywane animacje (bezpieczne dzięki safeliście).
  keyframes: true,

  // NIE zmieniaj na true — na zmiennych CSS stoi cały motyw.
  variables: false,
};

Krok 4 Uruchom 

npx purgecss --config purgecss.config.js

Powstanie plik css/molique-style.purged.css. Podmień na niego odwołanie w swoim HTML: 

<link rel="stylesheet" href="css/molique-style.purged.css">

Krok 5 Sprawdź, czy nic się nie zepsuło

Otwórz stronę i przeklikaj to, co używa JavaScriptu. Ta lista wyłapuje praktycznie wszystkie problemy:

  • Rozwiń akordeon i zakładki — czy animacja działa?
  • Otwórz modal i menu rozwijane w navbarze.
  • Kliknij zdjęcie w galerii (lightbox).
  • Wywołaj powiadomienie — czy ma kolor i pasek odliczania?
  • Przejdź na inną podstronę — czy aktywna pozycja menu się podświetla?
  • Przełącz motyw jasny/ciemny.

3. Gotowe konfiguracje

Wybierz swoje środowisko. Różni się głównie tym, gdzie PurgeCSS szuka nazw klas (content). 

const molique = require('./purgecss.safelist.cjs');

module.exports = {
  content: ['./**/*.html', './js/**/*.js'],
  css: ['./css/molique-style.css'],
  output: './css/molique-style.purged.css',
  safelist: molique.runtime,
  keyframes: true,
  variables: false,
};

Zainstaluj @fullhuman/postcss-purgecss i dodaj go jako wtyczkę PostCSS. Purge uruchomi się tylko przy budowaniu produkcyjnym. 

// postcss.config.cjs
const purgecss = require('@fullhuman/postcss-purgecss').default;
const molique = require('./purgecss.safelist.cjs');

module.exports = {
  plugins: [
    ...(process.env.NODE_ENV === 'production'
      ? [
          purgecss({
            content: ['./index.html', './src/**/*.{html,js}'],
            safelist: molique.runtime,
            keyframes: true,
            variables: false,
          }),
        ]
      : []),
  ],
};

Uwaga: w WordPressie duża część klas siedzi w bazie danych (treść wpisów, pola ACF, bloki), a nie w plikach. PurgeCSS ich nie zobaczy. Dlatego skanuj szablony PHP i koniecznie przeczytaj sekcję 4 poniżej. 

const molique = require('./purgecss.safelist.cjs');

module.exports = {
  content: [
    './wp-content/themes/moj-motyw/**/*.php',
    './wp-content/plugins/moja-wtyczka/**/*.php',
    './wp-content/themes/moj-motyw/js/**/*.js',
  ],
  css: ['./wp-content/themes/moj-motyw/css/molique-style.css'],
  output: './wp-content/themes/moj-motyw/css/molique-style.purged.css',

  // Klasy skladane w PHP nie sa widoczne - patrz sekcja 4.
  safelist: molique.merge('status', 'grid'),

  keyframes: true,
  variables: false,
};

4. Gdy backend skleja nazwy klas

To najczęstsza przyczyna „u mnie połowa stylów zniknęła". Jeśli budujesz nazwę klasy z fragmentów, w pliku nie ma jej w całości — PurgeCSS widzi tylko kawałki i wycina regułę.

Tak wygląda problem
<span class="badge badge-<?= $status ?>">

W pliku jest tylko badge-. Nazwy badge-success nie ma nigdzie, więc reguła znika.

Rozwiązanie
safelist: molique.merge('status')

Zachowuje całą rodzinę badge-*, więc każda wartość z bazy zadziała.

Włączaj tylko te grupy, których faktycznie używasz — każda zachowuje więcej CSS:

Grupa Obejmuje Włącz, jeśli sklejasz…
'status' badge-, status-, stock-bar-, overlay-, opacity- statusy z bazy, poziomy krycia
'grid' col-, offset-, grid-cols- szerokości kolumn z pola CMS
'colors' bg-, text-, border- kolory wybierane w panelu
'spacing' m-, p-, gap- odstępy generowane w pętli 
safelist: molique.runtime                      // minimum
safelist: molique.merge('status')              // + statusy z bazy
safelist: molique.merge('status', 'grid')      // + kolumny z CMS
safelist: molique.all                          // wszystko (najbezpieczniej)
Lepsze rozwiązanie, jeśli możesz

Zamiast sklejać nazwę, wypisz pełne klasy w kodzie i wybierz jedną — wtedy PurgeCSS je zobaczy i nie potrzebujesz żadnej dodatkowej grupy: $map = ['ok' => 'badge-success', 'err' => 'badge-danger'];

5. Czego nie robić

  • Nie ustawiaj variables: true — usunie zmienne CSS, na których stoi cały motyw (kolory, dark mode, zaokrąglenia). Strona straci wygląd.
  • Nie pomijaj safelisty, licząc że „chyba nic nie używa JS". Akordeony, powiadomienia i podświetlanie menu używają.
  • Nie zapomnij o js/ w content — jeśli Twój własny skrypt dodaje klasy, PurgeCSS musi widzieć ten plik.
  • Nie nadpisuj oryginalnego CSS wynikiem purge. Zapisuj do nowego pliku, żeby dało się wrócić.

6. Coś się zepsuło — co sprawdzić

Rozwiń objaw, który u siebie widzisz.

Komponent wygląda jak goły HTML (brak stylów)

Najpewniej brakuje safelisty albo jest niepodpięta. Sprawdź w konfiguracji, czy masz safelist: molique.runtime i czy ścieżka do purgecss.safelist.cjs jest poprawna.

Szybki test: wyszukaj w wynikowym CSS frazę lightbox-overlay. Jeśli jej nie ma — safelista nie zadziałała.

Kolory i motyw się rozjechały

Masz variables: true. Zmień na false i zbuduj ponownie. Motyw molique opiera się na zmiennych CSS — ich usunięcie zabiera całą paletę.

Statusy z bazy nie mają kolorów

Backend skleja nazwę klasy. Dodaj grupę: safelist: molique.merge('status'). Szczegóły w sekcji 4.

Aktywna pozycja w menu się nie podświetla

Wypadły klasy stanu .is-*. Pokrywa je molique.runtime — sprawdź, czy safelista jest podpięta i czy nie nadpisujesz jej własną listą.

Zysk jest znikomy (plik prawie się nie zmniejszył)

Prawdopodobnie używasz molique.all albo zbyt wielu grup. Zejdź do molique.runtime i dodawaj grupy pojedynczo, sprawdzając po każdej, czy wszystko działa.

Animationen & Mikrointeraktionen

Alles auf dieser Seite bewegt ausschließlich transform und opacity — das ist keine Vorliebe, sondern eine Voraussetzung für Flüssigkeit. Abschnitt 1 erklärt, warum. Fertige Effekte: Mikrointeraktionen und Eintritts-Animationen.

1. Warum nur zwei Eigenschaften

Der Browser zeichnet ein Bild in drei Schritten: Er berechnet das Layout (wo alles ist), malt Pixel und setzt Ebenen zusammen. Die animierte Eigenschaft entscheidet, wie viel davon sechzigmal pro Sekunde wiederholt werden muss.

Sie animieren Was neu berechnet werden muss Folge
width, height, top, margin Layout der gesamten Seite, Malen, Zusammensetzen verboten Die Größenänderung eines Elements verschiebt Nachbarelemente, der Browser berechnet das Layout also neu.
box-shadow, background-color, border-radius Malen und Zusammensetzen vermeiden Das Layout bleibt, aber die Pixel müssen neu gemalt werden.
transform, opacity Nur Zusammensetzen erlaubt Das erledigt die GPU, ohne Beteiligung des Haupt-Threads.
Wie man das umgeht, wenn es wirklich nötig ist

Ein Schatten, der wachsen soll, entsteht durch eine zweite Ebene mit einem fertigen Schatten und das Animieren ihrer Deckkraft — so funktioniert .hover-gpu-shadow. Das Ausklappen einer Höhe „bis wohin es eben reicht" erledigt .grid-expand, das grid-template-rows animiert. Die Regel ist also keine Einschränkung der Möglichkeiten, sondern eine Wahl des Wegs.

2. Eintritts-Animationen

Ein Element wartet unsichtbar, und sobald es in den sichtbaren Bereich fährt, erhält es vom Skript die Klasse .is-visible und erscheint sanft. Die Erkennung übernimmt ein Intersection Observer — kein scroll-Event, sodass bei jedem Pixel des Scrollens nichts berechnet wird. 

<!-- .animate ist PFLICHT - sie versteckt das Element zu Beginn -->
<div class="animate fade-in-up">Fährt von unten ein</div>

<!-- Kaskade: aufeinanderfolgende Elemente mit Verzögerung -->
<div class="animate fade-in-up">Erstes</div>
<div class="animate fade-in-up delay-100">Zweites</div>
<div class="animate fade-in-up delay-200">Drittes</div>
Klasse Rolle Was sie tut
.animate Basis Versteckt das Element und bereitet den Übergang vor. Ohne sie tut die Richtung nichts — siehe Fallstrick Nr. 1.
.fade-in Richtung Nur Erscheinen, ohne Bewegung.
.fade-in-up Richtung Einfahrt von unten — die häufigste Wahl. Weiter: .fade-in-down, .fade-in-left, .fade-in-right.
.zoom-in Richtung Das Element „nähert sich" durch Vergrößerung von 95 %.
.reveal-blur Richtung Scharfzeichnen aus der Unschärfe.
.reveal-scale Richtung Ein stärkerer Eintritt per Skalierung als .zoom-in.
.delay-100 – .delay-500 Modifikator Verzögerung in 100-ms-Schritten. Zum Aufbau einer Kaskade in einer Kartenreihe.
.is-visible Zustand Wird vom Skript gesetzt, sobald das Element sichtbar wird. Sie schreiben sie nicht selbst.

Eine Variante ohne JavaScript

.scroll-reveal macht dasselbe, wird aber von der Scroll-Position gesteuert, nicht von einem Skript. Der Fortschritt der Animation entspricht dem sichtbaren Anteil des Elements — Sie können also zurückscrollen, und der Effekt kehrt sich um. Erfordert einen neueren Browser; in einem älteren ist das Element einfach sofort sichtbar. 

<div class="scroll-reveal">Erscheint beim Scrollen</div>

3. Mikrointeraktionen

Eine Reaktion auf Hover. Sie funktionieren alle auf einem beliebigen Element — Karte, Button, Bild — und lassen sich kombinieren.

hover-scale
hover-tilt
Klasse Effekt JS
.hover-spring Federndes Abprallen. nein
.hover-scale Vergrößerung. Stärke: --hover-scale. nein
.hover-shadow Anheben mit Schatten. Höhe: --hover-y. nein
.hover-gpu-shadow Wachsender Schatten ohne Animation von box-shadow — eine zweite Ebene ändert die Deckkraft. nein
.hover-tilt Feste 3D-Neigung. nein

.ken-burns Ein langsamer Zoom in ein Foto innerhalb eines Containers. Funktioniert bei <img> und .bg-image. nein

Rahmeneffekte

Ein Rahmen, der sich beim Hover zeichnet. Zwei abgerundete Varianten und zwei mit scharfen Ecken — sie unterscheiden sich nicht nur im Aussehen, sondern auch im Mechanismus, was bei der Kombination mit einem Hintergrund wichtig ist.

Klasse Aussehen Mechanismus
.hover-border-draw Abgerundet, entfaltet sich aus der Mitte. Ein eigenes ::before — rührt den Hintergrund des Elements nicht an.
.hover-border-trace Abgerundet, Licht umläuft die Kontur. Ebenfalls ::before.
.hover-border-draw-2 Scharfe Ecken, Seite für Seite gezeichnet. Vier Gradienten im background-image des Elements — siehe Fallstrick Nr. 3.
.hover-border-trace-2 Scharfe Ecken, Kontur wird umlaufen. Wie oben.
Rahmenfarbe

Alle vier nehmen ihre Farbe aus --hover-border-color, standardmäßig --primary. Setzen Sie sie, wenn das Element bereits die Markenfarbe hat — sonst ist der Rahmen auf einem Hintergrund derselben Farbe unsichtbar.

4. Bewegung und Barrierefreiheit

Manchen Menschen wird von Animationen schwindlig oder übel — das vestibuläre System reagiert auf Bewegung auf dem Bildschirm genauso wie auf eigene Bewegung. Deshalb haben Betriebssysteme eine Einstellung „Bewegung reduzieren", und der Browser gibt sie als prefers-reduced-motion weiter.

Art der Bewegung Bei reduzierter Bewegung
Eine Hover-Reaktion Bleibt. Sie ist kurz und wird vom Benutzer ausgelöst.
Eintritts-Animationen Das Element erscheint ohne Bewegung.
Kontinuierliche Bewegung im Hintergrund Gestoppt. Betrifft u. a. .bg-blobs — die Animation erlischt, die Form bleibt.
Beim Schreiben eines eigenen Effekts

Das Framework schaltet Animationen nicht global stumm — das erledigt jede Komponente für sich, denn nicht jede Bewegung muss gestoppt werden. Wenn Sie eine eigene kontinuierliche Animation hinzufügen, ergänzen Sie deren Ausstieg: @media (prefers-reduced-motion: reduce) und animation: none.

5. Fallstricke

1 Eine Richtung ohne die Klasse .animate

.fade-in-up legt nur die Startverschiebung fest. Es ist .animate, das das Element versteckt und den Übergang definiert — ohne sie ist das Element sofort sichtbar und nichts passiert. Ein irreführendes Symptom, denn die Seite sieht korrekt aus, nur „ohne Animation". 

<!-- FALSCH - Basis fehlt -->
<div class="fade-in-up">…</div>

<!-- RICHTIG -->
<div class="animate fade-in-up">…</div>
2 Eine Eintritts-Animation auf sofort sichtbarem Inhalt

Eine Hero-Überschrift mit .animate startet unsichtbar und wartet auf das Skript. Führt JavaScript nicht aus — ein Fehler in einer anderen Datei, eine langsame Verbindung, eine Browser-Blockade — bleibt der Inhalt dauerhaft unsichtbar. Setzen Sie oberhalb des Folds Animation sparsam ein und lassen Sie die wichtigste Botschaft statisch.

3 Der -2-Rahmen unsichtbar auf farbigem Hintergrund

Die Varianten mit scharfen Ecken zeichnen ihre Linien mit Gradienten im background-image des Elements. Der background-color bleibt unberührt, sie funktionieren also technisch — aber die Linie hat standardmäßig die Farbe --primary, ist also auf einem .btn-primary-Button unsichtbar. Setzen Sie --hover-border-color auf eine kontrastierende Farbe. 

<button class="btn-primary hover-border-draw-2"
        style="--hover-border-color: #fff;">Weißer Rahmen</button>
4 Eine Verzögerungskaskade auf einer langen Liste

Die .delay-*-Klassen enden bei 500 ms, und das ist kein Versehen. Bei zwanzig Karten mit wachsender Verzögerung erscheint die letzte nach zwei Sekunden — für den Benutzer sieht das wie eine ruckelnde Seite aus, nicht wie ein Effekt. Verwenden Sie eine Kaskade für drei, vier Elemente in einer Reihe.

5 Animieren einer Eigenschaft außerhalb der beiden erlaubten

transition: all sieht harmlos aus, umfasst aber auch width, height und box-shadow — zieht also eine Layout-Neuberechnung durch die Hintertür mit hinein. Listen Sie Eigenschaften explizit auf. Erfordert der gewünschte Effekt eine verbotene Eigenschaft, suchen Sie einen Workaround aus Abschnitt 1: eine Deckkraft-Ebene statt eines Schattens, ein Grid statt einer Höhe.

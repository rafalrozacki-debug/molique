Vorschau

CLI molique-jit

Die Kommandozeile, mit der Sie die molique JIT-Engine bedienen: Bauen, Live-Watch-Modus, Konfiguration — dazu ein eigener Generator für fertige HTML-Bausteine.

Das ist eine Vorschau — das Paket ist noch nicht auf npm

Das auf dieser Seite beschriebene CLI existiert, funktioniert und wurde manuell verifiziert — das ist keine Ankündigung einer Funktion, die es noch nicht gibt. Das einzig wirklich Fehlende ist die erste Veröffentlichung des Pakets molique-jit im npm-Registry, weshalb npx molique-jit noch nicht „einfach so" funktioniert.

Bis dahin ist der schnellste Weg, es auszuprobieren, das Paket lokal aus dem Quellcode zu bauen — siehe Installation aus dem Quellcode weiter unten. Der Quellcode liegt offen im Repository: github.com/rafalrozacki-debug/molique.

1. Installation aus dem Quellcode (bis zur npm-Veröffentlichung)

Benötigt Node.js. Repository klonen und das Paket lokal bauen: 

git clone https://github.com/rafalrozacki-debug/molique.git
cd molique/tools/jit/package
npm install
npm run build

Ab jetzt verhält sich node dist/cli.js genauso wie npx molique-jit im Rest dieser Dokumentation — einfach das eine gegen das andere austauschen: 

node dist/cli.js init
node dist/cli.js build --minify
node dist/cli.js make:component

Dieser Abschnitt verschwindet, sobald das Paket veröffentlicht ist, und jedes npx molique-jit …-Beispiel unten funktioniert dann ohne Syntaxänderung — das CLI ist bereits für die vorgesehene Verwendung geschrieben.

2. Die Datei molique.config.mjs

Der Befehl init erstellt diese Datei für Sie, mit Kommentaren zu jedem Feld. Ein vollständiges, handgeschriebenes Beispiel: 

// molique.config.mjs
export default {
  // Wo nach Klassennamen gesucht wird.
  content: ['**/*.html', '**/*.php'],

  // Wohin das erzeugte CSS geschrieben wird.
  output: 'css/molique-jit.css',

  // NUR projektspezifische Klassen (z. B. in PHP zusammengesetzt).
  // molique-eigene Runtime-Klassen (Toasts, Karussell, .is-*-Zustände)
  // müssen hier nicht aufgeführt werden — die Engine bindet sie automatisch ein.
  safelist: ['badge-success', 'badge-danger'],
};

Bei mehreren unabhängigen Seiten in einem Projekt (z. B. der Hauptseite und einer separaten Kampagnen-Landingpage) ersetzt das Feld targets die obigen content/output-Felder und baut jedes Ziel unabhängig — die Landingpage bekommt ihre eigene, kleine CSS-Datei, ohne den Rest: 

export default {
  targets: [
    { content: ['src/**/*.html'], output: 'css/molique-jit.css' },
    { content: ['landing-kampagne.html'], output: 'css/landing-kampagne.css' },
  ],
};
Feld Standard Beschreibung
content ['**/*.html', '**/*.php'] Wo nach Klassen gesucht wird (Glob-Muster).
output css/molique-jit.css Pfad der Ausgabedatei.
safelist [] Klassen Ihres Projekts, die der Scan übersehen könnte (z. B. im Backend zusammengesetzt).
minify false Aktuell praktisch wirkungslos — die Quelldaten sind bereits an der Quelle komprimiert.
targets — Eine Liste unabhängiger Builds; wenn vorhanden, ersetzt sie content/output.

3. CLI-Befehle

Die Binärdatei heißt molique-jit (nicht nur molique), um Kollisionen mit anderen Tools mit kürzerem Namen zu vermeiden. Das CLI versteht Befehle auf Englisch, aber auch ihre polnischen und deutschen Entsprechungen — praktisch für Teams, die im Alltag eine dieser Sprachen verwenden.

Englisch (kanonisch) Polnisches Alias Deutsches Alias Was es tut
init start start Erstellt eine molique.config.mjs mit einer Beispielkonfiguration.
build buduj bauen Kompiliert CSS einmalig in die Ausgabedatei(en).
watch obserwuj beobachten Beobachtet Dateien und baut live neu (~50ms Debounce).
--minify / -m --minifikuj --minifizieren Erzwingt die Komprimierung der Ausgabe.
--config / -c --konfiguracja --konfiguration Verweist auf einen eigenen Konfigurationsdateipfad.

Alle drei Sprachvarianten tun genau dasselbe:

npx molique-jit init
npx molique-jit build --minify
npx molique-jit watch --config ./custom.config.mjs
npx molique-jit start
npx molique-jit buduj --minifikuj
npx molique-jit obserwuj --konfiguracja ./custom.config.mjs
npx molique-jit start
npx molique-jit bauen --minifizieren
npx molique-jit beobachten --konfiguration ./custom.config.mjs

Exit-Codes

build endet bei Erfolg mit dem Code 0 und bei einem Fehler mit 1 (z. B. wenn die Konfiguration auf einen nicht existierenden Ordner verweist) — praktisch zur Einbindung in CI, etwa als Schritt vor der Veröffentlichung.

4. Komponenten-Generator: make:component

Ein eigenständiger Befehl, unabhängig vom CSS-Build. Er startet einen interaktiven Assistenten im Terminal (Pfeiltasten + Enter) und gibt am Ende einen fertigen, einfügbaren HTML-Block aus — zeichengenau identisch mit den echten, funktionierenden Modal-Beispielen in dieser Dokumentation.

Aktueller Stand: Die erste Iteration des Generators unterstützt ausschließlich Modal (natives <dialog>) in den drei unten beschriebenen Varianten. Ein Generator für B2B-Tabellen und komplette Seitenvorlagen (als Idee in der Roadmap beschrieben) ist noch nicht implementiert — verlassen Sie sich nicht darauf, bis es hier erscheint. Das ist außerdem der erste Befehl der make:*-Familie — weitere (z. B. make:table) kommen zu diesem Abschnitt hinzu, sobald sie existieren. 

npx molique-jit make:component

Der Assistent fragt der Reihe nach ab:

Standard

Ein einfaches Modal: Titel, Inhalt, Auslöse-Button (Beschriftung + Farbe).

Confirm

Ein Bestätigungsdialog: Frage, Beschreibung, Beschriftungen für Abbrechen/Bestätigen, Aktionsfarbe (z. B. danger beim Löschen) und ein Warnsymbol.

Context

Ein seitliches Kontextmenü: Titel sowie die ersten zwei Aktionspunkte (Beschriftung + Symbol) — weitere fügen Sie manuell hinzu, indem Sie das erzeugte Muster kopieren.

Am Ende wählen Sie, ob der Code direkt in der Konsole ausgegeben wird (zum Kopieren mit der Maus) oder in einer Datei gespeichert wird — das Tool überschreibt eine vorhandene Datei nie ohne ausdrückliche Bestätigung.

Auf npm

molique JIT

Eine Engine, die nur das CSS erzeugt, das Sie tatsächlich verwenden — ohne PurgeCSS, ohne Safelist, ohne Raten. Bedient über die Kommandozeile — siehe CLI molique-jit.

Das Paket molique-jit ist auf npm veröffentlicht 

npm install --save-dev molique-jit
npx molique-jit init
npx molique-jit build

Vollständige Installation, Konfiguration und die komplette Befehlsübersicht stehen auf der Seite CLI molique-jit. Paketseite: npmjs.com/package/molique-jit.

1. Der Unterschied zu PurgeCSS

Die Seite PurgeCSS & Safelist beschreibt einen Ansatz „von groß nach klein" — Sie nehmen das komplette, kompilierte molique-CSS und schneiden alles heraus, was in Ihren Dateien nicht gefunden wird. Das funktioniert, erfordert aber eine Safelist (weil manche Klassen erst durch JavaScript hinzugefügt werden) und birgt ein Risiko: Übersieht PurgeCSS etwas und Sie vergessen die Safelist, hört eine Komponente lautlos auf zu funktionieren.

molique-jit geht den umgekehrten Weg: Es startet bei null und fügt nur die Klassen hinzu, die es tatsächlich als literalen Text in Ihren HTML-/JS-Dateien gefunden hat. Es löscht nie etwas, daher gibt es nichts, was man in einer Safelist „vergessen" könnte — Klassen, die von JavaScript ausgelöst werden (Toasts, Lightbox, .is-*-Zustände), sind fest in die Engine eingebaut, genau wie in der fertigen PurgeCSS-Safelist.

PurgeCSS (heute verfügbar) molique-jit (Vorschau)
Startpunkt Das komplette kompilierte molique-style.css Nichts — fügt nur passende Klassen hinzu
Braucht eine Safelist Ja, manuell eingebunden (purgecss.safelist.cjs) Nein — Runtime-Klassen sind in die Engine eingebaut
Live-Watch-Modus Muss separat verdrahtet werden (z. B. PostCSS-Plugin) Eingebaut: watch
HTML-Komponenten-Generator Keiner 8 make:*-Generatoren (siehe CLI)

Sie müssen sich nicht für immer entscheiden

Beide Wege lösen dasselbe Problem (eine kleinere Produktions-CSS-Datei) auf unterschiedliche Weise. molique-jit ist eine einfachere, konfigurationsfreie Alternative zu PurgeCSS für neue Projekte — die PurgeCSS-Seite bleibt für alle, die es lieber in eine bestehende Build-Pipeline einbinden.

2. Funktionsweise (kurz erklärt)

Die Utility-Klassen von molique (.pb-md-4, .text-hover-primary usw.) sind nicht beliebig — sie bilden eine endliche, vollständig bekannte Menge, die einmal beim Kompilieren des Frameworks berechnet wird. Deshalb berechnet die JIT-Engine niemals CSS zur Laufzeit — stattdessen arbeitet sie wie ein Wörterbuch:

1

Scannt

Liest Ihre Dateien (HTML, JS, PHP — was auch immer Sie über content angeben) und extrahiert jedes Token, das wie ein Klassenname aussieht.

2

Gleicht ab

Prüft jedes Token gegen ein fertiges Wörterbuch von molique-Klassen (ein Nachschlagen, keine Berechnung). Ein Token außerhalb des Wörterbuchs ist einfach Ihre eigene Klasse — kein Fehler.

3

Kopiert

Gibt fertige CSS-Regeln 1:1 aus dem echten, kompilierten Framework aus und erhält dabei die @layer-Reihenfolge.

Ergebnis: Die Ausgabedatei ist Byte für Byte identisch mit dem, was das vollständige molique-style.css für dieselben Klassen liefern würde — die Engine erfindet oder berechnet nichts selbst.

Wie verwendet man das?

Sie steuern die Engine mit init/build/watch über die Kommandozeile — Installation, die Konfigurationsdatei, die vollständige Befehlsübersicht (mit polnischen und deutschen Aliassen) und der HTML-Komponenten-Generator stehen auf einer eigenen CLI-Seite.
